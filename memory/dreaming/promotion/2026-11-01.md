## ⭐ 本周期最重要的三条

**① recall store 的写入触发器是 `memory_search` **工具**，不是 CLI —— 第六次验证「查询驱动」并首次精确到通道层（第 125 条）**
- 对照实验：先连跑 **3 次 CLI `openclaw memory search --agent main`**（三条不同查询）→ `Recall updated` **纹丝不动**停在 `2026-10-31T19:14:01.677Z`
- 随后改用**进程内 `memory_search` 工具**（同一 workspace，同一主题）→ `Recall updated` **立刻推进到 `2026-11-01T19:06:16.014Z`**，spaced **387 → 384**，新增条目 `memory/2026-11-01.md:212:228`（maxScore 0.8961）
- **结论**：CLI 走独立进程、不带 owner 上下文，**不写 recall store**；只有 Gateway 进程内的工具调用才计数
- **实践含义**：① 养候选**必须用工具，不能用 exec 里跑 CLI**；② 巡检脚本若用 CLI 判"recall store 是否活"，**必然假阴性**

**② skill-collection-review 9 个任务全部 ok —— 11-01 遗留的"验证窗口是下个 7 天周期"立即闭环（第 127 条）**

- 逐条回溯 receipt：10-31 22:29 起约 50 轮 skipped，但 **11-01 09:29 / 21:10 / 21:59 三轮 `ok`**（对应主会话有活动）
