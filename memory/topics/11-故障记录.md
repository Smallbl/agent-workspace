## 2026-04-01 cron任务超时问题

- **现象：** 所有定时简报任务（AI早报、AI晚报、工作AI简报、OpenClaw日报）连续两天失败，状态为 error
- **根本原因：** cron 任务超时设置默认为 30 秒，但简报生成+搜索+发送需要 50-180 秒
- **解决方案：** 将所有简报任务的 timeoutSeconds 从默认值改为 180 秒
- **修复命令：**
  ```
  openclaw cron edit <job-id> --timeout-seconds 180
  ```
- **涉及任务：**
  - ai-morning-briefing (3f650a3a...)
  - openclaw-daily-news (29418b9f...)
  - ai-work-briefing (9130e296...)
  - ai-evening-briefing (d697e753...)
  - memory-daily-backup (b142b71c...) → 60秒即可
- **经验教训：** 新增 cron 任务时注意检查超时设置，默认 30 秒可能不够用

## 2026-04-29 Gateway 凌晨被 LaunchAgent 杀死（严重）

- **现象：** 凌晨 06:00:04 Gateway 收到 SIGTERM，挂掉 1 小时 27 分，直到王手动执行 `openclaw gateway run` 才恢复
- **根因：** 两个本该禁用的 LaunchAgent plist 仍在被 launchd 调度：
  1. `gateway-restart`（05:00）：调用 `/usr/bin/openclaw gateway restart`，路径不存在，每5分钟重试共28次
  2. `gateway-daily-restart`（06:00）：执行 `launchctl bootout` 杀死 gateway
- **为什么"禁用"了还运行：** macOS launchd 对 `.disabled-` 前缀文件名只是 community convention，**launchd 仍然会加载并调度**。正确做法是 `launchctl bootout` + 物理移走文件
- **修复：**
  1. `launchctl bootout` 两个任务
  2. 物理移走 plist 到 `~/Library/LaunchAgents/disabled-backup/`
- **附带发现：**
  - 03:00 Memory Dreaming 的 light/rem/deep 三阶段全部 timeout，疯狂重试
  - 微信第二账号 `aa1b373441f2-im-bot` 启动 crash：`Cannot read properties of undefined (reading 'logger')`
  - OpenClaw 已升级到 v2026.4.25（之前的 daily-restart plist 仍标记 v2026.4.14 需要更新）
- **教训：**
  1. `.disabled-` 前缀不可靠，禁用 LaunchAgent 必须 bootout + 移走文件
  2. LaunchAgent 里不要用 `$(id -u)` shell 展开，在 launchd 环境可能失效
  3. 不要用 `launchctl bootout` + `bootstrap` 做定时重启（风险高），改用 `openclaw gateway restart`

## 2026-04-15 飞书文件上传权限修复

- **现象：** 飞书机器人无法发送Excel附件，只显示为文本路径
- **根本原因：**
  1. 飞书机器人缺少 `drive:file:upload` 等drive权限
  2. 发送文件时用 `file_type=stream` 而不是其他类型
- **解决方案：**
  1. 在飞书开放平台给机器人开通权限：
     - `drive:drive`
     - `drive:file`
     - `drive:file:upload`
  2. 上传文件用 `file_type=stream`：
     ```
     POST https://open.feishu.cn/open-apis/im/v1/files
     ```
  3. 发送文件消息用 `file_key`（不是 `file_token`）：
     ```
     POST https://open.feishu.cn/open-apis/im/v1/messages
     msg_type: file
     content: {"file_key":"...", "file_name":"xxx.xlsx"}
     ```
- **备注：** 文件名含中文时API可能只识别为文本，改用ASCII文件名或先上传到drive再发消息更可靠
