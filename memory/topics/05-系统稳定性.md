### memory promote 返回 0 候选属预期行为（2026-10-27 03:47 → ✅ 已澄清，非故障）

- **此前反复排查的方向错误**：连续多个周期把"`promote` → candidates=0"当作记忆插件故障去排查，实际是**打分门槛的正常表现**
- **根因（查 OpenClaw 源码 `dist/short-term-promotion-*.mjs` 确认）**：门槛判定为 `candidate.score < minScore`，而 `score` 是**六维加权综合分** —— frequency .24 / relevance .30 / diversity .15 / recency .15 / consolidation .10 / conceptual .06；**`maxScore`（相似度峰值）只是 relevance 一项的输入，不是门槛值**
- **复算验证**：以本机真实候选反推打分模型，重算得 0.6343，与线上 `promote --json` 上报值 0.6343 完全吻合（误差 <0.0006），模型可信
- **真正的瓶颈**：`diversity = uniqueQueries / 5` 与 `consolidation`（recallDays 天数与间隔，跨 4 天以上且间隔越远分越高）→ 同一主题必须被**多个不同查询**、在**多个不同自然日**命中才会累积到门槛
- **结论**：不必再为"0 候选"排查插件/索引；要提速只能让查询**措辞多样化并跨日复用同一主题**
