## 最新资讯

### 📌 1. OpenClaw 2026.6.5 正式发布：速度与安全双提升

6月上旬，OpenClaw 发布了2026.6.5 版本，带来多项重要改进：

### 📌 2. TaskFlow：让 AI 任务拥有持久化工作流

4月最重磅的更新是 TaskFlow 编排层——它让 AI 任务有了持久化的工作循环：
- 可以管理多步骤、长周期、跨会话的任务
- 支持子任务拆分、状态跟踪、失败恢复
- 可以实现多Agent协作（如：用强模型做调度、用便宜模型做执行）

这对我们的项目跟踪场景非常有价值——可以设计一个"项目进度检查"的工作流，定期运行、自动更新、异常时告警。

👉 原文链接：https://www.mindstudio.ai/blog/openclaw-april-2026-update-new-features-agentic-runtime

### 📌 3. Memory Wiki 新增"来源追溯"功能（Providence Labels）

OpenClaw 的记忆系统现在能追踪每条记忆的来源，分四类：
- Observed（观察）：AI 从文件、消息、日志中读取
- Confirmed（确认）：用户明确验证过
- Inferred（推断）：AI自行推断，未经验证
- Imported（导入）：从对话历史中引入

这对于记忆管理非常重要——我们一直强调"记忆要可靠"，Providence Labels 正好帮助区分哪些是可信的、哪些是AI推断的。

👉 原文链接：https://www.mindstudio.ai/blog/openclaw-april-2026-update-new-features-agentic-runtime

### 📌 4. 多模型运行时切换：无需重建工作流

OpenClaw 新增 Provider Manifest，支持在运行时切换不同模型：
- 可选：GPT-5.5、Claude、Gemini、DeepSeek、Ollama、Gemma 4
- 切换模型无需重建工作流
- 可以用强模型做调度、便宜模型做执行，降低成本

这意味着我们可以针对不同任务使用不同性价比的模型，比如简单查询用 DeepSeek，复杂分析用 Claude。

👉 原文链接：https://www.mindstudio.ai/blog/openclaw-april-2026-update-new-features-agentic-runtime

### 📌 5. 安全加固：插件安装策略全面升级

2026.6.2 起，OpenClaw 改变了插件安装机制：
- 从旧的"危险代码扫描"改为"操作员安装策略"，更安全
- 修复了多项安全漏洞：组提示词隔离、危险命令包装器屏蔽、不安全Node环境覆盖阻止等
- 设备/节点角色审批现在需要管理员权限

对于在企业内部使用来说，安全加固非常重要，可以更好保护系统不被滥用。

👉 原文链接：https://patchbot.io/ai/openclaw

## 【豆浆学习笔记】

### 🔍 对我们的价值分析

**1. TaskFlow 是我们最值得尝试的新特性**
- 我们有很多"定期检查"类任务（如检查项目状态、会议提醒、系统巡检）
- TaskFlow 可以让这些任务持久化运行，不依赖对话上下文
- 建议：先在测试环境试试"每日项目进度检查"工作流

**2. Memory Providence Labels 值得借鉴**
- 我们在 MEMORY.md 里也应该标注信息来源（用户确认 vs AI推断）
- 可以避免未来把AI推断当事实用的错误
- 建议：在记忆文件里加一个"可信度"标记

**3. 多模型切换适合我们的成本优化**
- 我们用 MiniMax M2，价格相对经济
- 简单任务可以继续用 MiniMax，复杂推理任务可以尝试 Claude
- OpenClaw 现在支持这个能力，值得配置试试

**4. 安全加固是长期利好**
- 我们是招标代理机构，系统里有很多敏感信息
- 新版安全机制让我们用起来更放心

### ⚠️ 需要注意的风险
- OpenClaw 版本更新频繁（几乎每两天一个版本），我们用的是 2026.5.28，最新已是 2026.6.5
- 建议下次 gateway 重启时考虑升级到最新稳定版
- 升级前先跑一下 `openclaw doctor` 检查兼容性
