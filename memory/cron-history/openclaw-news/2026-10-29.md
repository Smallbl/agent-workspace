【OpenClaw日报】📅2026-10-29

📌 当前运行版本：OpenClaw 2026.9.5 (ec9c1a1)｜官方最新稳定版：2026.10.7（10月24日发布）

━━━━━━━━━━━━━━━━━━━━

**1. OpenClaw 2026.10.7 发布：会话恢复、升级备份与跨平台应用大修**
最新版 2026.10.7 于 10 月 24 日发布，核心是"可靠性"：升级恢复时会把应用自带的插件自动收敛到升级后的核心版本，并在数据库结构变更后自动还原被锁死的 Agent 状态（含系统 Agent）；会话恢复改为"可重放"模式，中断的会话能保留未完成的工具调用结果，重启 Gateway 后不丢活。同时新增 Gemini 4 Argon 模型支持，macOS 首次安装引导也更顺滑。对我们最直接的影响：以后升级 OpenClaw 时，豆浆的 Agent 记忆库和定时任务状态不会再因为结构迁移而"变砖"。
原文链接：https://releasebot.io/updates/openclaw

**2. 2026.10.6 起强制要求打过补丁的 Node.js 运行时（重要升级前置条件）**
从 2026.10.6 开始，OpenClaw 要求 Node 24.22.1+（24 线）或 26.12.1+（26 线），原因是 2026 年 10 月 Node.js 安全更新修复了被入侵的证书签名密钥链。Docker 镜像已内置 Node 24.22.1；如果本机 Node 版本过低，`openclaw update` 会直接拒绝安装并给出修复指引，而不是把现有安装搞坏。⚠️ 我们这台 Mac mini 当前是 Node v26.7.0，**低于 26.12.1 要求**，升级 OpenClaw 前必须先升 Node。
原文链接：https://releasebot.io/updates/openclaw

**3. 2026.10.5 大版本：2704 次提交、2250 个 PR、638 位贡献者**
这是近期最heavy的一次主干发布。关键变化是"托管更新收敛"——升级过程中官方插件会被对齐到应用管理的核心版本，并保留诊断信息以便修复路径不丢。此外该版本还包含大量会话/记忆索引、Control UI、Discord 命令、Codex 预览的稳定性修复。10.5 是这次 10 月发布列车的主干，10.6/10.7 是在其上的加固补丁。
原文链接：https://github.com/openclaw/openclaw/releases

**4. 2026.9.34 扩展稳定版（等同 LTS）发布：安全补丁 + 渠道投递可靠性**
这是官方当前对标 LTS 的"扩展稳定版"，只做可靠性修复不引入新特性，但安全意义不小：修复了 WhatsApp 重试与贴纸、Telegram 相册与双栈回复、Slack 中继恢复、Discord 语音通话回复的丢消息/重复消息问题——这些正是多渠道消息"发出去但没回音"类故障的根源。同时主机重启后能回收 Worker 容量、部分克隆 worktree 可自修复缺失对象，Gateway 重启后子任务结果与 exec 唤醒证据不再丢失。对我们天天依赖飞书/定时任务的环境很关键。
原文链接：https://releasebot.io/updates/openclaw

**5. Microsoft Autopilot 基于 OpenClaw 构建，OpenClaw Enterprise 以 MIT 协议开源**
微软在 4 天内发布了基于 OpenClaw 的常驻 Copilot Agent（Autopilot），同时 OpenClaw 基金会把 OpenClaw Enterprise——一个面向持久化 Agent 的企业级控制平面（由 OpenAI、Red Hat、NVIDIA 背书）以 MIT 协议开源。重要信号：微软生态正在把 OpenClaw 当作默认 Agent 运行时，OpenClaw Enterprise 免费开源意味着"企业版"不是收费阉割版。王的公司在招投标数字化上若有系统级 Agent 落地需求，这套开源控制平面是很好的架构参考。
原文链接：https://openclaws.io

**6. 2026 年 OpenClaw 安全记录：722 条公告、14 条严重漏洞**
第三方审计梳理了全部公开安全公告：2026 年累计 722 条安全公告，其中 14 条为严重级别；9 月单日集中发布了 75 条公告。不同网站给出 138、543 等不同数字，是因为统计口径不同（是否含重复/回溯修订）。核心结论：OpenClaw 迭代极快，早期版本（尤其 6 月前安装的）必须先升到 9.5 再往上跳，中间有大版本迁移不能盲升。
原文链接：https://openclaws.io

**【豆浆学习笔记】**

读完这批更新，我提炼了 4 条对我们工作流真正有价值的结论：

**① 版本落后不是小事，但升级前有一个硬门槛。** 我们跑在 2026.9.5，最新已经到 2026.10.7，中间跨了 10.5 这个大版本。10.5 的 2704 个提交里包含插件版本对齐机制——这对我们很重要，因为我用的是「核心 + 飞书插件」的组合，官方在 9.5 里就明确说过「单独升级插件不够，必须核心和插件一起升」。**行动项：升级前先备份 ~/.openclaw/，跑 `openclaw doctor` 看废弃字段，再升 Node 到 26.12.1+，最后用 `bash ~/.scripts/safe-gateway-restart.sh` 重启（不要直接 restart，会丢正在处理的消息）。**

**② 「回放式会话恢复」直接命中我们的痛点。** 我们用 Gateway + cron 做每日简报、多Agent派发，最怕的就是重启后定时任务结果丢失。2026.10.x 的可重放恢复和「cron announce 唤醒时保留 CLI 会话、不重置 provider session」这条修复，正是我们这种「定时任务 + 常驻会话」架构需要的。**值得升级到 10.7 后专门压测一次：升级后故意重启 Gateway，看日报任务能否完整续跑。**

**③ 渠道投递可靠性的修复，比新功能更值钱。** 我们通过飞书单向推送，任何一条丢失或重复都是实际事故。9.34 修的那批 Telegram 相册/双栈回复、Slack 中继恢复、Discord 语音回复丢失问题，说明多渠道投递的边界情况确实多。**建议：升级后把"飞书消息必须带原文链接 + 存档文件"这条作为投递校验项，我可以顺手写个自检脚本，比人工盯更靠谱。**

**④ 对我们业务最有参考价值的是 OpenClaw Enterprise 的架构，而非某个具体功能。** 王做招投标数字化（多项目、供应商多、子系统交叉、会议多、需要跟进进度），这本质上就是一个「多Agent + 持久记忆 + 审计追溯」的控制平面问题。官方把 Enterprise 以 MIT 开源、并有 OpenAI/Red Hat/NVIDIA 参与，说明这条路是成熟且免费的。**建议方向：拿我们现有的「豆浆主控 + 子Agent派发 + memory/ 归档」架构去对照 Enterprise 控制平面的能力清单，看缺什么（比如权限审批、任务审计、集中观测），这是给王做技术中心 AI 落地规划时的一张现成参考地图。**

另记一条：安全公告数量巨大（722 条），说明「用旧版本裸奔」比想象中危险得多。我们的 Node v26.7.0 也已低于官方要求的 26.12.1，属于该修的技术债。
