二、资讯 5 条

1. 【2026.11.1：纯补丁版，主修"消息被拒 + Doctor 假成功 + 配置写入卡死"】
官方原文：This patch release adds no new features. It fixes accepted messages being refused, failed Doctor inspections reported as successful, and Gateway configuration writes getting stuck. 规模 83 PR / 91 commits / 67 contributors。
为什么重要：这是"稳定性止血"版本，不是功能版本。对我们最直接的痛点是飞书流式文本跨工具调用丢失、动作卡片格式错误，以及 Telegram/Discord 已受理消息被误拒。
https://docs.openclaw.ai/releases/2026.11.1

2. 【Doctor 从"永远成功"变成会失败的检查器】
原文：Doctor now returns a nonzero exit code in these cases（检查被阻断、最终配置非法、必需迁移被推迟时）；无人值守的 Doctor 报告缺失插件但不会自动安装，除非加 --fix/--repair/--yes。
为什么重要：我们的巡检脚本如果只判 exit code，今天之前会把"检查失败"误判成"一切正常"。这条值得马上对照我们的自动化脚本。
https://docs.openclaw.ai/releases/2026.11.1

3. 【飞书专项修复：流式文本丢失 + 动作卡片格式】
原文：Fixes Feishu losing streamed text across tool calls and sending action cards in the wrong format。
为什么重要：王的飞书是主渠道，这条直接命中我们"回复跨工具调用后文字变残缺"的老毛病。
https://docs.openclaw.ai/releases/2026.11.1

4. 【2026.9.36（extended-stable）重点是收紧边界而非加功能】
Highlights 原文要点：失败的 npm 回滚不再让已装包丢失；tools.fs.workspaceOnly 约束可下推到 Gateway 构建的工具；Microsoft Teams 名字键 allowlist 解析不到时一律拒绝；畸形媒体元数据/邮件地址/TOML/URI/超大集合不再引发无界工作；emoji 等星平面字符之后的比较文案不再被出站清洗器吞掉。
为什么重要：这是当前 stable 线里安全收敛做得最彻底的一版，适合生产环境承接。
https://docs.openclaw.ai/releases/2026.9.36

5. 【Node.js 安全地板高于 OpenClaw 的 engines 门槛】
2026-10-21 Node 安全发布：修复 10 个漏洞（4 个高危），最严重为 Brotli 解码器越界写 CVE-2026-111497，Node 官方称"permits remote code execution"，CVSS 4.0 = 9.2。修复版本：22.23.4 / 24.22.1 / 26.12.1。
必须区分：
- engines 准入门槛（npm 会不会拒绝）：2026.11.1 只要 >=24.16.0 <25 || >=26.1.0
- Node 安全补丁地板（建议升到的修复版本）：26.12.1 / 24.22.1 / 22.23.4
二者不互斥，安全地板可以高于 engines。release notes 原文没有写"在旧 Node 上拒绝安装"，所以不能写"会拒绝"。
https://nodejs.org/en/blog/vulnerability/october-2026

【豆浆学习笔记】
1. 版本策略：当前 latest=2026.11.1、extended-stable=2026.9.36、beta=2026.11.5-beta.1。生产建议先跳到 2026.9.36（安全收敛版，Node 门槛也已提高到 24.22.1/26.12.1），功能需求再评估 2026.11.1。但本机 Node 26.7.0 两边都不满足 engines，先升 Node 再升 OpenClaw，顺序不能反。
2. Node 安全地板优先于 OpenClaw 自身版本：CVE-2026-111497 是 RCE 级（Brotli 越界写），我们 Gateway 跑在 Node 上，本机 26.7.0 落在受影响的 26.x 线内，这是本周最高优先级的动作。
3. Doctor 语义变了：以后自动化巡检必须判 exit code，而不是看输出里有没有 ERROR。我们的 2 个孤儿 agent 目录（agent-frontend / backend-agent）正好印证铁律里"派发前必须补全 agents.entries"，否则子 Agent 的模型和身份会走默认值。
4. 飞书是主渠道，2026.11.1 对飞书流式文本和动作卡片的修复值得优先升级验证——这是每天都在踩的痛点。
5. Advisor 特性（2026.10.10 引入，Settings → System → Labs）与我们 AGENTS.md 里"子 Agent 回复前两行自检"是同一思路，可作为对照：Advisor 用额外模型调用做纠偏，我们是零额外成本用流程约束纠偏。可以在一次真实派发中并测两者效果。
6. 待观察：2026.11.5-beta.1 在仓库 CHANGELOG 目录与 docs release notes 站点均无对应文件（已做阳性对照：同目录 2026.11.1.md 存在且可读），暂无可引用的官方发布说明，不能对其内容做任何断言。
