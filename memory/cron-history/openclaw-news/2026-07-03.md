📌 一、OpenClaw v2026.6.11 发布：专注稳定性打磨

这是继 4 月底一系列稳定性问题之后的核心补丁版本。官方坦言"这周很难熬"，Gateway 出现性能下降、部分安装陷入插件依赖修复循环、Discord/Telegram/WhatsApp 频道集体抖动。v2026.6.11 重点修复：

• Copilot 支持在对话流程中向用户提问并接收回答，改善了会话状态可见性
• 修复 Gateway 重启后旧进程（如 Codex/Claude adapter）残留导致新会话卡顿的问题
• 定时任务和内置工具执行成功率提升，SDK 运行时更稳定
• CLI 命令（doctor/config/shell completion）给出更清晰错误提示和恢复指导

→ 影响：v2026.5.28 已在此之后发布，说明核心稳定性已逐步修复。定期关注 Gateway 重启后进程状态。

━━━━━━━━━━━━━━━━━━━━━━━━

📌 二、OpenClaw v2026.6.8 更新：频道体验大幅改善

本次更新让 Telegram 和 WhatsApp 两大平台的消息渲染更可靠：

• Telegram：支持结构化文本（表格、列表、块引用、保留换行）、CLI 风格回复
• WhatsApp：终于正确遵循配置的 ACP 绑定
• 新增用量页脚（usage footers），清晰显示 token 消耗
• Web 搜索默认行为更可预测，敏感操作保持显式授权

→ 影响：我们目前通过飞书渠道使用，这部分改进不直接影响，但"用量透明"对预算管理有参考价值。

━━━━━━━━━━━━━━━━━━━━━━━━

📌 三、内存与记忆系统持续进化

多个版本持续改进内存可靠性：

• Session 历史记录增加上限（caps），防止长对话导致上下文溢出
• 内存活动（active/reset/deleted）与配置的 session store 对齐，Dirm/QMD 导出和索引不再漏记或错位
• "Dirm"（动态内存管理）在真实使用中表现更稳定

→ 影响：对我们的飞书消息管理、项目跟踪等长期记忆场景直接利好。值得关注即将到来的 Memory Wiki 功能更新。

📌 四、OpenClaw × NVIDIA：强化 Agent Skill 安全

6 月 1 日，OpenClaw 官方宣布与 NVIDIA 合作，共同推进 Agent Skill 安全生态。这次合作的主要方向：

• Skill 安全扫描器（safety scanner）成为官方标配
• Token 用量仪表盘集成，帮助运营者掌握实际消耗
• 官方支持 Opus 4.6 和 GPT-5.6 模型家族
• NVIDIA NemoClaw 引入沙箱执行、策略强制和受控运行时环境，服务企业级生产部署

→ 影响：对我们这种需要管理多个子系统的场景，Skill 安全扫描 + token 可视化是直接需求。

━━━━━━━━━━━━━━━━━━━━━━━━

📌 五、OpenClaw 发布 LTS 版本计划，承诺"更小、更可靠"

经历 4 月底稳定性危机后，官方宣布：

• 将推出 LTS（长期支持）版本，与快速迭代版本并行
• 核心正在"瘦身心"，把可选功能迁移到 ClawHub，减小主安装体积
• 核心原则："OpenClaw 必须保持无聊般的稳定（boringly reliable）"

→ 影响：对于生产环境使用者，LTS 版本意味着更可控的升级节奏。建议关注 ClawHub 作为插件生态的扩展路径。

截至 2026 年 6 月，OpenClaw GitHub Stars 已突破 150,000，npm 周下载量 416,000+。NVIDIA CEO 黄仁勋公开评价 OpenClaw 为"或许是软件历史上最重要的发布之一"。

【豆浆学习笔记】

1. **对我们最有价值的更新是 v2026.6.x 系列的稳定性修复**。我们的工作流高度依赖飞书频道 + 定时任务，这些更新直接影响豆浆的可靠性。

2. **Skill 安全扫描器**值得特别关注。我们目前用了多个 skill（飞书系列、天气等），但从未系统审计过这些 skill 的权限边界。建议近期做一次 skill 安全检查。

3. **Token 用量仪表盘**对我有参考价值——虽然飞书渠道本身不单独计 token，但了解整体消耗有助于评估成本结构。

4. **内存系统改进**（Session caps + Dirm 稳定性）是直接利好。豆浆的记忆依赖这些底层机制，更稳定 = 我更可靠。

5. **ClawHub 生态扩张**值得关注。我们目前 skill 较少，但未来可以探索 ClawHub 上的社区 skill（如 Notion、更多数据库连接器），扩展豆浆的能力边界。

6. **LTS 版本**建议在我们自己的 Mac mini 上优先使用。如果未来有 LTS 分支，我会建议王考虑切换，以获得更稳定的生产体验。

—— 豆浆，2026-07-03
