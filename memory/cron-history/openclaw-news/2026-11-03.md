1. 2026.10.9 稳定版发布：安全与可靠性为主基调
这是一次以"安全 + 可靠性"为核心的更新：修补了有漏洞的运行期依赖（fast-uri、Zod 集合膨胀、nodemailer 发件人伪造、Teams 的 MSAL Node），修复了 SQLite 分词器变更导致的数据库与全文索引损坏，更新失败回滚现在会保留运维人员的手工改动而不是重置 checkout。同时把 `tools.fs.workspaceOnly` 应用到 Gateway 构建的工具上，委派/子代理的文件改动仍需审批，媒体类工具不得越出工作区——这直接收紧了多 Agent 协作时的越权面。

2. 2026.9.35 / 2026.9.36 扩展稳定版（extended-stable，即当前 LTS 线）
这条线只发安全、可靠性、性能补丁，不带新功能，自动更新也不会动它。9.36 加强了工作区与 Microsoft Teams 的访问控制，限制了不可信输入的边界；新增 Kimi K3.1 Pro、较老的 xAI 模型支持；修复了 Codex 回合预算被静默回退、OpenAI OAuth 目录过期失效、Anthropic 用 setup-token OAuth 时 PDF 分析失败、MCP 会话超时拖垮下一回合等问题，还支持了 Tailscale Serve/Funnel 在 tailscaled 重启后自愈。
为什么重要：我们这台 Gateway 是"有人在用的生产设施"，这类"只修不改"的通道更符合王"更新要稳"的偏好。

3. OpenClaw 2.0（v2026.8.1）：浏览器端成为一等主界面 + 云端共享会话
2.0 是本代架构的基线：安装流程大幅简化（自动探测电脑上已有的 ChatGPT/Claude 订阅、API Key、本地模型），大部分配置改到启动后的对话里完成；Web 应用被重写为"主界面"而非附属控制台——直接进入对话即可配置 Agent、监控任务、操作工作流；同时引入共享云会话（shared cloud sessions），多人可以带着同一上下文进入同一个 Agent 会话，任务可在同事之间交接。社区反馈两极：有人升级顺滑，也有人遇到网关起不来、自动化任务丢失、模型认证失败。

4. OpenClaw Enterprise（OCE）发布：面向企业的"Agent 的 Kubernetes"
9 月 29 日官方公告，定位为厂商中立的控制平面：给持久化 Agent 加上安全边界与可审计记录，让 IT/安全团队能签字放行，而不是一刀切禁用 Agent 平台。GitHub README 自称"Kubernetes for agents"，每个团队有独立 Namespace 与凭证。OpenAI 内部已在用（Androidclaw：构建失败时定位 PR 并修复、追溯故障、发布带视频证据的修复并合入），Red Hat 也在试点。仍在 1.0 之前的开发阶段。

【豆浆学习笔记】
今天读完这批内容，最有价值的三点：

一、升级策略要分层。本地 2026.9.5 落后 stable 通道 4 个版本，stable 通道节奏是"每 2-3 天一个小版本、9 月一个月发了 12 个"，9.9.6 甚至把 Mac App 弄崩过（Apple silicon 启动即崩）。建议：生产 Gateway 走 extended-stable（`openclaw update --channel extended-stable`），只在有明确需求时才升 stable；每次升级前备份 + `openclaw doctor --fix` + 重启验证，这与我们 AGENTS.md 里"改配置前先备份"的规矩一致。

二、2.0 的"共享云会话"最值得试。这几乎是为我们团队场景写的——技术中心多个项目、多个子系统并行推进，现在豆浆的会话是个人闭环；多人带同一上下文进入同一会话、任务可在同事之间交接，意味着"豆浆"可以从"王一个人的助手"变成"项目组的共享工作台"。这条值得下一步专门试跑一次（注意配合 2.0 的 workspace/Teams 访问控制，别让上下文无限暴露）。

三、权限收紧和技能审核两条，跟我们的安全红线直接相关：`tools.fs.workspaceOnly` 已覆盖 Gateway 构建的工具，委派也要审批——这正好支持 AGENTS.md 里"主 Agent 绝不自己写代码、必须派发子 Agent"的铁律，基础设施层面帮我们兜住了。ClawHub 技能 36.8% 存在安全问题的抽样结果也提醒：以后装第三方技能前先看来源，我们现在装的 tavily、feishu 等 plugin 应定期复核。

另外两点备忘：企业版 OCE 尚在 1.0 前，但"给 Agent 加可审计的权限与记录"的思路值得借鉴到我们内部系统——王在招标代理行业推进数字化时，AI 落地的第一道门槛往往就是审计与合规；Microsoft 的 Copilot Autopilot 已把 OpenClaw 当底座，说明这条路上下游都在动。王关注的"AI 在招投标行业落地"，我现在能提供的差异化点就在这套治理与审计能力上——建议后续把"Agent 操作留痕、权限分级、可回溯"作为我们内部落地的第一条技术要求。

最后一句实话：今天没有一条是"颠覆性"的新功能，2.0 之后半年基本在打磨工程可靠性。对我们来说这不是坏事——把基建做扎实，比追新版本更重要。
