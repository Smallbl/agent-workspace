【1】v2026.10.9 安全与可靠性补丁：收紧凭据处理与工作区边界
官方在 10 月底连发三个安全版本，10.9 是其中最重要的一次。它修复了一条会把应用凭据发往错误目标的路由漏洞（涉及 Microsoft Teams 与 Azure 登录），并升级 fast-uri 4.2.3 用于拒绝畸形地址。同时 "仅限工作区"（tools.fs.workspaceOnly）限制扩展到 Gateway 构造的委派工具与媒体读取工具：受控委派必须走审批，媒体读取不会越出允许的文件夹。官方在检查类视图中对活跃凭据做了脱敏（原始本地日志与模型可见的工具输出不变）。这次是纯补丁、零新功能，规模为 38 个 PR、8 次直接提交、22 位贡献者。
为什么重要：这是我们判断"要不要尽快升"的第一优先级——凭据外泄和工作区越界的风险点在我们的多 Agent 委派 + 飞书文件读写场景里是真实存在的。
原文链接：https://docs.openclaw.ai/releases/2026.10.9

【2】v2026.10.8 / v2026.10.6：eMudhra 证书泄露事件与 Node 版本硬门槛
10.8 是另一个安全版本，针对 secret egress proxy 及其导出信任包中 eMudhra 证书泄露的修复；10.6 是同一事件的第一次响应。关键影响：OpenClaw 现在要求 Node 24.22.1+（Node 24 分支）或 26.12.1+（Node 26 分支），旧版 Node 构建仍信任受影响的证书。Docker 镜像和官方安装器已用打过补丁的版本，但我们是自管 Node，必须自己升。10.6 还带来了一个对我们很有用的可选开关：agents.defaults.compaction.midTurnPrecheck.enabled=true，可以让活跃运行在收到大段后续消息后继续跑而不重复已完成的工具调用；另有技能依赖可从通用下载链接解包压缩包、Memory Wiki 状态查询加速、Doctor 不再改动非法 UTF-8 的工作区笔记。
为什么重要：证书门槛是硬性的，不升 Node 就等于带着漏洞跑；midTurnPrecheck 则直接关系到我们长文档处理时会不会重复劳动。
原文链接：https://docs.openclaw.ai/releases/2026.10.8 ｜ https://docs.openclaw.ai/releases/2026.10.6

【3】腾讯 AIG 加入 ClawScan：技能供应链安全检测再加一层
腾讯朱雀实验室的 A.I.G 扫描器加入 ClawScan（可组合的技能安全扫描框架），与 NVIDIA 的 SkillSpector 并行独立扫描每个上传到 ClawHub 的 skill/plugin，再由一个 AI 裁判综合两份结果与源文件给出最终结论。A.I.G 是"LLM 驱动的多阶段代码审计与漏洞审查流水线"，覆盖九类风险：指令劫持、记忆污染、远程载荷执行、未授权访问、持久化、不安全依赖等。配套发布了 SkillTrustBench 基准集（含良性/可疑/恶意样本）。腾讯方面还同步推出了 EdgeOneClawScan 技能包，用户在对话框里说一句话就能完成"配置体检 + 技能审计 + CVE 漏洞扫描 + 隐私权限评估 + 自然语言风险报告"。
为什么重要：我们装第三方 skill 的行为越来越频繁，而 skill 供应链投毒是 OpenClaw 当前最现实的攻击面。
原文链接：https://openclaw.ai/blog/tencent-aig-joins-clawscan ｜ https://github.com/openclaw/clawscan

为什么重要：这既是官方路线图的风向标，也给技术中心提供了一个"把内部使用痛点反馈回上游"的正式通道。

【豆浆学习笔记】

一、版本落后了，需要排一次升级窗口
我们跑在 2026.9.5，官方已到 2026.10.9，中间隔了 10 个版本，且 10.6/10.8/10.9 三个都是安全版本。升级前必须做的三件事：
1）查 Node 版本，低于 24.22.1 / 26.12.1 必须先升 Node，否则装了新版仍信任 eMudhra 的坏证书；
2）我们已经在 2026.9.5，正好符合"6 月前的旧安装必须先经过 2026.9.5 中转"的硬性要求，路径是通的；
3）按 AGENTS.md 的铁律走：先备份 ~/.openclaw/，再 `openclaw doctor` 查废弃字段，再升级，最后 `openclaw doctor --fix` 补迁移。重启 Gateway 必须用 `bash ~/.scripts/safe-gateway-restart.sh`，绝不用裸 `openclaw gateway restart`，否则正在处理的飞书消息会丢。

二、直接可以落地到我们工作流的三件事
1）workspace-only 收紧是双刃剑。好处是子 Agent 不会乱跑目录、飞书文件读取不会越界；代价是"委派"这类动作可能需要审批。我们 AGENTS.md 里的多 Agent 派发模式要提前确认这条策略，否则会出现子任务卡在审批上。
2）midTurnPrecheck 值得开。我们每天处理招标文件、PDF、评审意见这类长文本，开启后不会因为后续追加消息而重跑已完成的工具调用，对 token 和时间都是实打实的节省。
3）EdgeOneClawScan 值得试装一次给我们自己做体检。我们的 skill 来源混合了官方、自建和第三方安装，体检报告是低成本的保险。

三、对"AI + 招投标"这个主线的启发
10 月这批更新的主线其实只有一个词：可信（trustworthy）。官方在安全上持续加码——技能扫描双引擎、AI 裁判、技能安全卡片、凭据脱敏、工作区边界——说明 Agent 生态已经进入"企业敢用"的阶段。对我们这种要做招投标数字化的团队来说，这恰恰是利好：竞争对手在比 Agent 能力时，能证明"我的 Agent 不会泄露标书、不会越权、每一步可审计"才是真正的门槛。技术中心的定位不该只是"把 AI 装上"，而应该是"把 AI 装成可审计、可交付、可投标的"。

四、值得尝试的新特性
1）Focus Weeks 机制——可以关注后续主题（首期是 Control UI），如果我们遇到某个交互卡点，可以直接提 issue 参与，这对公司内部推广 AI 工具有示范价值。
2）OpenClaw Enterprise（9 月 29 日开源，MIT 许可，OpenAI/Red Hat/NVIDIA 背书）——这是"在敏感环境里管理常驻 Agent 的控制平面"，对标我们公司内多系统、多供应商的协同场景，值得王关注一下这条线。

五、结论
今天没有"必须立刻动手"的重大功能更新，但有"必须排期处理"的版本债与安全债。建议本周内：先升 Node（不依赖 OpenClaw，风险低）→ 备份 → 升到 2026.10.9 → 跑 doctor --fix → 验证飞书链路 → 装 ClawScan 做一次体检。
