【本地版本】OpenClaw 2026.9.5 (ec9c1a1) ｜ 上游最新稳定版：2026.10.9（2026-10-29 发布）

---

### 1. 官方发布 2026.10.9，并强制抬高 Node.js 运行时下限
OpenClaw 10 月底连续发布 2026.10.6 → 10.9，主线是稳定性、安全与性能修复，覆盖 Gateway、Agent 会话、模型供应商、消息通道、语音与桌面端。同时从 2026.10.9 起强制要求 Node 24.22.1+ 或 26.12.1+（对应 2026 年 10 月 Node.js 安全发布中证书密钥被攻破的 TLS 链问题），`openclaw update` 会在旧 Node 上拒绝安装并给出恢复指引，而不是直接把线上服务搞挂。
为什么重要：我们当前跑的是 2026.9.5，比上游落后约 10 个版本，且长期稳定版（extended-stable / LTS 线）已到 2026.9.36，其中包含一批关键的更新失败可回滚、消息投递可靠性修复。生产环境应该规划一次带备份的升级。
原文链接：https://github.com/openclaw/openclaw/releases ｜ https://docs.openclaw.ai/releases

### 2. Skill Workshop 2.0：技能可审阅、可对比版本、可撤销回滚
2026.10.5 带来的 Skill Workshop 2.0，把「编辑、版本对比、归档/恢复、Undo 回滚」集中到同一个界面，可以查看助手学到的技能发生了哪些变化并一键还原旧版本。同时新增后台学习开关（可设为 Off 停止后台学习与闲置技能清理，仍可用 `/learn` 手动触发；注意后台学习会把对话与工具内容发给你配置的模型供应商，可能产生费用）。
为什么重要：这直接命中「记忆持久性与可靠性」这条核心诉求——技能从黑盒变成可审计、可回退的资产。
原文链接：https://docs.openclaw.ai/releases/2026.10.5

### 3. 2026.10.1：已安装技能发现 + MCP Apps + 完整备份到外置/R2
Agent 现在可以在需要时检索已安装技能，而不必把整个技能库塞进提示词（嵌入式 Agent、Code Mode、Codex 会话均支持），选中后再单独读取完整指令；读取指令不等于获得安装或执行权限。MCP Apps 支持在主聊天旁以「可选加入」方式运行。完整备份可写入本地外置硬盘或 Cloudflare R2 对象存储，恢复时先落到全新暂存目录，避免直接覆盖线上文件。
为什么重要：技能检索让「技能库越来越胖但实际用不到」的问题得到解决；备份到 R2 意味着我们可以在异地留一份可恢复副本，正好契合 AGENTS.md 里「配置/安装前必须先备份」的红线。
原文链接：https://docs.openclaw.ai/releases/2026.10.1

### 4. 2026.9.9 / 9.8：模型扩容 + 「更新翻车」恢复链路加固 + 代理间通信修复
9.9 加入 Codex 的 GPT-6.1 Sol 与 Claude Haiku 5.5（`haiku` 别名默认指向 5.5，自适应思考默认开启，注意超 10 万 token 提示词涨价），并系统性加固更新失败恢复：更新失败后可恢复兼容安装、更新期间写入数据不丢、回退到 9.8 后仍能继续升级。9.8 修复了子 Agent 之间传话丢失（`REPLY_SKIP`/`ANNOUNCE_SKIP` 会吞掉整个回复）以及 Codex 多代理并发时的内存占用，并修复「飞书带说明文字的附件丢失」「定时任务超时误杀同会话新对话」。
为什么重要：这一串修复几乎全是我们日常会踩的坑，尤其是子代理结果回传丢失和飞书附件丢失——我们正处于「多子 Agent 编排」路线上。
原文链接：https://ai.saiita.com.cn/openclaw-2026-10-updates ｜ https://releasebot.io/updates/openclaw

### 5. 生态与商业化动向：OpenClaw Enterprise 控制面与早期试点
10 月下旬官方频道与社区开始放出 OpenClaw Enterprise 的控制面（control plane）、安全边界、可审计性以及早期试点计划；同时 ClawCast 播客讨论了用本地模型（如 NVIDIA RTX Spark）跑 OpenClaw 的取舍——隐私 vs 算力成本。社区侧 ClawHub 技能生态持续扩张（如腾讯云 WorkBuddy 的 SkillHub 即基于 OpenClaw 生态构建，宣称 7 万技能、两月下载超 3000 万次）。

## 【豆浆学习笔记】

1. **升级优先于新功能。** 本地 2026.9.5 已落后上游约 10 个版本，而 9.8/9.9 修的恰好是我们最在意的两类问题：子 Agent 结果回传丢失、飞书附件丢失。建议排一次「备份 → 升级到 2026.9.36 稳定线 → 观察」的升级动作，而不是长期停留在旧版。注意 2026.9.6 在 macOS 上有启动崩溃的已知问题，不要停在那儿；升级前务必备份 config 与 workspace。

2. **Skill Workshop 2.0 与我们的「铁律」高度互补。** 我们规定主 Agent 不写代码、要派发专业子 Agent，但目前技能是靠我自己在会话里「学会再记住」的，缺少版本管理和回滚。2.0 提供的版本对比 + Undo，正好可以作为「技能变更可追溯」的落地载体：每次我把一条新做法固化成技能，都能保留旧版本，需要时一键回退。

3. **后台学习要主动关掉或设限。** 2.0 新增的后台学习开关会把对话与工具内容送到模型供应商并可能产生费用。我们涉及招投标项目、客户信息、内部系统，属于高敏感场景，默认应设为 Off，改为按需 `/learn` 手动触发，技能只在明确有用时沉淀。

4. **备份路径可以升级到 R2。** 2026.10.1 支持完整备份直传 Cloudflare R2，且恢复走暂存目录不覆盖线上文件。这解决了我们现在「备份文件堆在 Mac mini 本机」的单点风险——本机挂了，配置和记忆一起丢。建议配一个 R2 bucket 做每日增量备份。

5. **技能检索（installed-skill discovery）值得立刻受益。** 我们技能目录正在变长（climbedhub、feishu-*、taskflow 等），全量注入提示词既烧 token 又稀释注意力。升级后按需检索 + 按需读取完整指令，正好是我想要的模式。

6. **值得尝试的新特性：** ① MCP Apps 旁挂运行（可以让轻量 UI 类工具在聊天旁独立工作）；② Skill Workshop 的版本对比（做技能变更审计）；③ R2 备份 + 暂存恢复（升级/迁移安全网）；④ Haiku 5.5 作为轻量任务的廉价模型（定时任务摘要、文件归档这类不需要强模型的活可以降本）。

7. **待确认事项：** 本地 Node 版本是否已达 24.22.1+/26.12.1+（本机 node=v26.7.0，看起来满足 26 线）；升级路径上要避免在 beta 与稳定版之间横跳。
