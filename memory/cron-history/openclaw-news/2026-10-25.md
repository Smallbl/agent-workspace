【OpenClaw日报】📅2026-10-25

本地运行版本：OpenClaw 2026.9.5 (ec9c1a1) ｜ 官方最新稳定版：2026.10.6（2026-10-22 发布）

【资讯一】官方发布 2026.10.6 紧急安全补丁，修复 eMudhra 证书泄露
10 月 22 日发布的 2026.10.6 是一次纯安全修复版本（无新功能），专门修补 eMudhra 证书颁发机构（CA）被入侵导致的证书信任链泄露问题。这意味着之前由 OpenClaw 签发/校验的 TLS 证书可能已被视为不可信，需要尽快更新本地 Node 运行时：Node 24 需升到 24.22.1 及以上，Node 26 需升到 26.12.1 及以上，再启动 OpenClaw。该版本同时修复了大量会导致安装、更新、启动失败的问题，包含 233 个 PR、30 次直接提交、149 位贡献者。
原文链接：https://docs.openclaw.ai/releases/2026.10.6
参考链接：https://github.com/openclaw/openclaw/releases

【资讯二】2026.10.4 修复「群聊冒充」权限漏洞，聊天标签页也能自动恢复
10 月中旬的 2026.10.4 里有一条重要安全修复：未通过验证的群组私聊（DMs）发送者不再能获得 owner 权限、审批动作和提权工具调用——此前可被冒充者借此操纵代理执行敏感操作。此外 Web UI 增加了「聊天刷新」能力：升级前开着的标签页卡在「Server updated」时，刷新即可回到原对话链接，不会丢上下文。版本还修复了 Tailscale 残留路由阻塞启动、休眠/时钟回拨导致的误中断等问题。
原文链接：https://docs.openclaw.ai/releases/2026.10.4

【资讯三】2026.10.5 大幅优化会话与内存性能，长对话更流畅
2026.10.5 是性能向的大版本：新会话首屏更快，图片密集的长对话不再重复解码缩放已存储图片；接受到的 Memory 索引在 provider 等待期间保留执行器；数据库调用次数下降，Gateway 回调不再被模型目录刷新阻塞。子代理（subagent）工作完成后恢复的答案保持完整，耗时与父级运行用量可覆盖整个请求；注入的报告和告警只出现一次，不会打断正在进行的回复。对我们这种「主控 + 子Agent」架构，这一条最直接相关。
原文链接：https://docs.openclaw.ai/releases/2026.10.5

【资讯四】ClawHub 技能安全审查引入腾讯 AI-Infra-Guard，恶意技能检出率 98.6%
10 月 2 日 OpenClaw 宣布腾讯的 AI-Infra-Guard 加入 ClawScan 技能与插件安全审查流程。在 SkillTrustBench 基准（腾讯与港中大共建、556 个固定样本）上，OpenClaw 报告与基准标签一致率 86.9%，恶意样本正确识别率 98.6%。背景是 Snyk 今年 2 月对 3,984 个技能的审计中，发现 36.8% 至少含一个安全问题、13.4% 含严重问题、76 个含恶意载荷。官方同时明确：这些是基准样本结果，不等于全量目录的实际检出率。
原文链接：https://www.gradually.ai/en/openclaw-statistics

【资讯五】跨组件信任机制加固：远程节点默认不可信，插件安装默认 fail-closed
2026 年 3–4 月那波被社区称为「史上最密集安全块」的改动持续在后续版本里生效：远程节点事件默认标记为不可信并在进入主代理上下文前被净化，堵住被劫持节点注入「System:」提示词的路径；WebSocket 会话在 token/密码轮换后立即失效；技能加载增加 realpath 校验，强制留在指定根目录内；插件安装默认改为 fail-closed，未验证插件需显式 `dangerously-force-unsafe-install` 才能装；插件只允许访问 manifest 中声明的资源。TAR/ZIP 解压也加固了对符号链接逃逸与子 symlink 穿越的攻击。
原文链接：https://petronellatech.com/blog/openclaw-ai-agent-guide-2026
官方文档：https://docs.openclaw.ai/releases/2026.8.1

【豆浆学习笔记】

一、版本差距：我们在 2026.9.5，官方已到 2026.10.6，跨了 4 个版本 + 1 个安全补丁版。最紧迫的不是功能，而是 2026.10.6 的 eMudhra 证书泄露修复——**已实测本机 Node 为 v26.7.0，不满足 2026.10.6 要求的 Node 26 ≥ 26.12.1**（若走 Node 24 通道则需 ≥ 24.22.1）。证书信任链可能在近期失效，届时飞书连接、模型请求会大面积报错。**建议：先升级 Node 到 26.12.1+，再升级 OpenClaw 到 2026.10.6。**

二、可以直接搬到我们工作流里的三件事：
1. **子代理耗时统计**：2026.10.5 让 subagent 完成后的恢复回答带上完整耗时与父级运行用量。我们的「主Agent只调度不写码」铁律正需要这类可量化证据来复盘派发质量——以后每派一个前端官/后端官/测试官，都能自动拿到真实耗时，不用我自己估。
2. **告警不打断回复**：注入的报告和告警只出现一次、不打断正在进行的回复。这对飞书双渠道同步尤其有用——处理过程中不再需要反复发"进度同步"消息来规避刷屏，异常报告能干净地跟在结论后面。
3. **队列消息跨重启存活**（2026.10.6）：排队中的消息和正在写的回复现在能挺过 Gateway 重启。我们这套「改配置 → 安全重启 → 消息不丢」的流程风险会明显降低，AGENTS.md 里"重启会丢消息"的顾虑可以放宽。

三、必须警惕的坑：
- 插件安装默认 fail-closed + 插件只能访问 manifest 声明资源 → 升级后如果某个插件（比如飞书插件）报错，第一反应应该是查 manifest，而不是反复重装。这条对我们尤其重要，因为飞书通道是主链路。
- 技能加载新增 realpath 校验 → 我们的 workspace 里有 `~/.openclaw/plugin-skills/` 软链结构，升级后如果技能加载异常，先确认路径是否越界。
- 群组私聊冒充权限漏洞已在 2026.10.4 修复 → 我们只在王的私聊里发指令，但若将来把代理接入群聊，这条是硬门槛。

四、值得尝试的新特性：
- **本地语音合成**（2026.4.10 起，MLX 框架，Apple Silicon 本地跑）：王是 Mac mini，语音输入输出可以完全本地化，不走云 API，不产生语音费用也不外传音频。适合做"早上听简报"的语音版日报。
- **ClawHub 安全信号 + 腾讯 AI-Infra-Guard**：我们每次从 ClawHub 装技能前，可以先查该技能是否在恶意样本库中，98.6% 的检出率对日常装技能来说已经够用。
- **extended-stable（类 LTS）发布频道**：`openclaw update --channel extended-stable` 可以拿到稳定性优先的版本，日常生产环境建议锁定这个频道，而不是追 beta。

五、行动项（下次心跳执行）：

2. 确认是否升级到 2026.10.6（升级前必须备份，schema 迁移不可逆）。
3. 评估是否切换到 extended-stable 频道。
