## 近期重要更新

### 1. 新增 SGLang 和 vLLM 本地模型服务支持
**时间：2026年5月13日**

OpenClaw 文档新增了两个重要的本地模型服务提供商的配置指南：SGLang 和 vLLM。这两个都是自托管的 OpenAI 兼容接口服务，允许用户运行本地大模型。

**为什么重要：**
- 对于需要数据隐私或希望使用自有GPU资源的用户来说，这是重大利好
- 可以用来跑 ollama、LM Studio 等本地模型，或者直接对接私有化部署的模型服务
- 文档：https://docs.openclaw.ai/gateway/local-model-services

**原文链接：**
- https://docs.openclaw.ai/providers/sglang
- https://docs.openclaw.ai/providers/vllm

---

### 2. OpenRouter 统一API支持完善，新增图像和视频生成
**时间：2026年5月12日**

OpenRouter 现在不仅支持多模型对话，还支持通过统一API进行图像生成和视频生成。

**为什么重要：**
- OpenRouter 的特点是"一个 API key 访问多个 LLM"
- 对于需要灵活切换模型或使用不同厂商能力的场景非常有用
- 结合图像和视频生成能力，可以实现更丰富的多媒体处理工作流

**原文链接：**
- https://docs.openclaw.ai/providers/openrouter

## 豆浆学习笔记

### 对我和我的团队的价值分析

1. **本地模型部署能力增强（SGLang/vLLM）**
   - 我们公司做招标代理，项目数据敏感，有时候不方便把数据发送到外部API
   - 现在可以用 OpenClaw + 本地模型来处理一些内部任务
   - 可以探索"本地模型 + 飞书通知"的组合，减少数据外传风险

2. **OpenRouter 统一入口**
   - 现在的 AI API 费用波动大，OpenRouter 可以让我们更灵活地切换不同提供商的模型
   - 结合图像和视频生成能力，可以考虑一些自动化的文档/演示生成场景

3. **xAI Grok 接入**
   - Grok 的风格比较幽默、有个性，如果需要生成有特色的内容可以尝试
   - 但目前优先级不高，可以先观望

4. **多渠道消息集成（飞书、Telegram等）**
   - 我们已经在用飞书，这是正确的选择
   - OpenClaw 的 channel 配置支持多账号，可以探索更多自动化场景

### 可以尝试的方向

- 用 OpenClaw 做项目进度的自动提醒（定时检查飞书消息、汇总项目状态）
- 用本地模型处理敏感的项目文档摘要（不外传）
- 探索 Canvas 功能做可视化的工作流展示

### 整体感觉

OpenClaw 最近几个月的更新重点是"让 agent 更易用、更灵活"，尤其是对各种模型和 API 的兼容性在持续增强。版本号 2026.5.18 说明开发节奏很稳定，跟着社区走不会有大问题。
