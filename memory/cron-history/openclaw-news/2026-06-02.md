# OpenClaw 日报 — 2026-06-02

## OpenClaw 2026.6.1-beta.2 发布 — Agents 可靠性大幅提升

**概要：** 2026年6月1日发布的最新测试版，重点改善了 Agents 和 CLI 运行时在中断后的恢复能力。从工具调用中断、会话绑定僵死、压缩交接，到媒体重试恢复，都有更干净的清理逻辑。同时通道（Discord、Telegram、WhatsApp、Slack、Teams 等）和移动端 delivery 稳定性全面提升。

**为什么重要：** 此前版本在长时间运行或复杂工作流中容易出现"挂起"问题，新版本对超时、锁释放、事件队列等底层机制做了系统性修复。对我们日常运行定时任务、飞书集成等场景，可靠性提升直接受益。

**原文：** https://github.com/openclaw/openclaw/releases

## OpenClaw 核心安全改进 — 公开透明的安全加固历程

**概要：** 官方博客详细披露了过去几个月安全加固的完整过程。包括：核心压缩（减小攻击面）、插件沙箱化、OpenTelemetry/Prometheus 可观测性集成、凭证管理从"请小心"升级为强制引用机制、Cisco 安全评估后的修复（认证 bug、权限混淆、重连范围扩大、沙箱绕过等）。

**为什么重要：** 文章明确指出 OpenClaw 已成为全球最多人观看的 AI Agent 项目，"透明"是其安全进化的核心驱动力。这对我们理解信任边界、配置安全策略有重要参考价值。

**原文：** https://openclaw.ai/blog/openclaw-security-in-public

## ClawHub Skill 安全验证升级 — 预发布校验 + Hugging Face 数据集开源

**概要：** ClawHub 新增三项安全机制：（1）预发布签名验证，（2）NVIDIA Skill Cards 卡片展示，（3）SkillSpector 风险分析。同时将扫描结果数据集开源发布在 Hugging Face，供社区研究和改进 Agent Skill 安全。

**为什么重要：** OpenClaw 的灵活性来自 Skill/插件生态，但"任何 Skill 都能跑"也意味着风险。安全验证体系的建立，标志着 OpenClaw 从"玩具"向"生产级基础设施"迈进的里程碑。我们安装新 Skill 时将更有信心。

**原文：** https://releasebot.io/updates/openclaw

## OpenClaw 4月底故障官方回应 — 核心精简进行中，LTS 计划5月公布

**概要：** 官方首次承认4月底的"艰难一周"：4.24 起 Gateway 变慢、部分安装卡在插件依赖修复循环、各通道行为异常。根因是插件依赖修复逻辑同时跑在启动和更新路径上，捆绑插件和外部插件半分离，ClawHub 元数据尚未稳定。官方承诺：核心将继续精简，非核心功能全部迁至 ClawHub，LTS 长期支持版将于5月单独公布。

**为什么重要：** 这是一次罕见的官方坦诚。了解故障根因，有助于我们判断未来升级策略——尤其是大版本升级时需格外关注启动路径变化。我们的 Mac Mini 作为单一机器部署风险相对小，但仍建议关注 LTS 版本。

**原文：** https://openclaw.ai/blog/openclaw-rough-week

## NVIDIA NemoClaw 发布 — 企业级安全 AI Agent 运行环境

**概要：** NVIDIA 推出 NemoClaw，将 OpenClaw Agents 运行在 OpenShell 沙箱环境中，后者精确定义 Agent 能做什么和不能做什么。同时支持本地 DGX Spark 部署，运行 Nemotron 等开源模型，适合大规模 Token 推理任务。

**为什么重要：** 对于需要数据隐私（患者记录、法律文档、财务数据）的大规模企业场景，本地部署 + 严格沙箱是刚需。OpenShell 的权限边界机制值得我们在设计高敏感操作（如招标数据处理）时参考借鉴。

**原文：** https://blogs.nvidia.com/blog/what-openclaw-agents-mean-for-every-organization

## 【豆浆学习笔记】

**对豆浆和团队的价值分析：**

1. **稳定性优先**：4月底故障说明"快速迭代"有代价。我们在升级前应关注 changelog 中的"破坏性变更"标记，可用 `openclaw doctor --fix` 做预检再动手。

2. **安全是长期课题**：官方博客的态度值得学习——坦诚问题、系统修复、不回避批评。我们在推进 AI 落地时，也应建立类似的安全事故记录和复盘机制。

3. **ClawHub Skill 安全验证**对我们直接有用：安装新 Skill 前可关注是否有 NVIDIA Skill Card 或 SkillSpector 标记，减少恶意/高风险 Skill 入侵风险。

4. **定时任务可靠性提升**：新版本对 Cron 和中断恢复的改进，对我们的"每日简报自动推送"等场景是直接利好——任务中断后能更干净地恢复，不丢状态。

5. **值得尝试的新特性**：
   - 如果要跑高敏感数据（招标文件、供应商报价），可研究 OpenShell 沙箱机制的落地方式
   - ClawHub 新上线的 Skill Cards 可作为 Skill 选型的安全参考维度
   - 关注即将发布的 LTS 版本，作为生产环境的首选

**一句话总结：** OpenClaw 正从"功能爆发期"转入"安全可靠期"，这对我们在生产环境长期使用是积极信号。下一步重点关注 6 月正式版和 LTS 版本发布。
