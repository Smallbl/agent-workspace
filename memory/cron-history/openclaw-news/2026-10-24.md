【OpenClaw日报】📅2026-10-24

**本地版本：** OpenClaw 2026.9.5 (ec9c1a1)　|　**官方最新稳定版：** v2026.10.5

---

**1. 2026.10.5 正式版发布：2704 次提交、2250 个 PR、638 位贡献者的大版本**
官方在 10 月中旬释出 2026.10.5，这是 2026 年 10 月的第三个正式版本，规模空前（2704 commits / 2250 PRs / 638 contributors）。核心方向是"更稳的更新、更快的恢复、更严的密钥脱敏"，同时把子代理（subagent）投递、Gateway、CLI、移动端、macOS 端的各种问题一并修掉。对我们最直接的含义：本机还停在 2026.9.5，中间跨了 9.10、10.1、10.2、10.3、10.5 五个版本，且 10.2 起"从 2026.10.1 首次升级即可干净完成"，升级风险已明显降低。
原文链接：https://github.com/openclaw/openclaw/releases

**2. 2026.10.x 主线：更新机制与"崩溃恢复"成为头等公民**
10.2 的官方说明第一条就是"从 2026.10.1 起的第一次升级现在能干净完成"，10.5-beta.2 继续加固：更新流程会主动收拾"陈旧的交接租约、已完成的回执、遗留的 2026.9.8 恢复记录"，不再卡在"update-recovery-pending"；Windows 短路径、跨设备/跨文件系统升级、Windows 提权中断都能自愈。10.10-beta.3 进一步补上"schema 变更后恢复 agent 存储（含系统内置 agent）"和"迁移回滚备份只针对被改动的表"。这对我们是实打实的好消息——自动更新不再有"升级到一半炸掉"的风险。
原文链接：https://releasebot.io/updates/openclaw

**3. 2026.10.5：记忆系统与子代理审批的双重加固**
2026.10.5 的修复清单里，记忆相关改动密度最高：冷启动不再把所有记忆索引全部打开（恢复 2026.10.4 的启动内存表现）、插件重载后记忆文件继续被索引、插件重载不再在慢速"dreaming 清理"时超时；同时明确"自动保存记忆的回合不得重新获得无关工具、不得改动项目文件"——这等于给 memory 工具加了一层权限护栏，正好符合我们"主 Agent 不自己写代码、只做调度"的原则。此外工具调用与子代理的审批控制也被加强，长会话在主模型冷却时可通过健康的 fallback 模型继续摘要与续接。
原文链接：https://docs.openclaw.ai/releases/2026.10.5

**4. 2026.10.2：密钥脱敏与提示词缓存命中率提升**
这一版有几条对我们日常运维很实用的改动：OpenAI 与 Anthropic 的 API Key 路径默认启用"provider 原生压缩"；跨越 chunk 边界的长工具输出中的凭据现在会被正确掩码（此前有泄漏风险）；Anthropic 的会话检查点在追问与重启之间保持字节级一致，使缓存前缀持续命中（意味着成本和首字延迟下降）。同时子代理回答不再被截断或被迟到的回执覆盖——这是连续第二个版本修子代理投递问题。
原文链接：https://cellcog.ai/blog/openclaw-2-0

**5. 2026.10.1 / 10.3：会话记忆健壮性、Codex 模型支持与 LTS 通道**
2026.10.1 聚焦"会话与记忆"：注册表变更后仍保留用量数据、从远程工作区投递 worker 附件、避免排队取消与转录别名卡住活跃回合、批量迁移嵌入缓存并报告超长行。2026.10.3 则是 gateway-only 的 extended-stable（等价于 LTS）通道，叠加关键安全更新与新模型支持；10.1 还支持"对话即技能"（把过去的对话转成可复用技能）与 GPT Image 2.5、终端内交互式提问。9.7 版另外加入了 OpenAI Agents API 与"Sign in with ChatGPT (Beta)"。
原文链接：https://docs.openclaw.ai/releases/2026.10.1

**【豆浆学习笔记】**

**一、版本落后已成事实，建议尽快升级**
本地 2026.9.5 vs 官方 2026.10.5，差了五个版本、约两个月。值得注意的是 9.7（2,818 PR）和 10.5（2,250 PR）这种量级的版本，说明当前版本号已经无法反映实际功能密度——我们按"小版本号"理解风险会误判。

**二、三条可直接落到我们工作流里的改进**
1. **"自动记忆保存回合不得改动项目文件、不得获得无关工具"** —— 这条几乎是按我们 AGENTS.md 铁律写的。以后如果我出现"自己上手写代码"的倾向，这条护栏会在系统层直接拦住。可作为巡检项。
2. **子代理投递连续两个版本被修（10.1、10.2）** —— 我们大量依赖子Agent做开发/测试派发。此前偶发"子代理结果被截断或被迟到回执覆盖"，是真实的可靠性痛点。升级后需重新验证一次派发链路。
3. **密钥跨 chunk 边界掩码 + API Key 路径默认 provider 原生压缩** —— 我们的飞书凭据、模型 Key 都在配置里，长工具输出中泄漏凭据是可想象的风险。优先升级能拿到这层修复。

**三、值得试用的新特性**
- **"对话即技能"（Chat to Skill，2026.9.4 起）**：把历史对话直接转成可复用 Skill。我们的飞书里那些"怎么写简报""怎么排版回复"的固定套路，完全可以沉淀成 Skill，收益直接。
- **Active Memory / Grounded Dreaming（2.0 起）**：后台"做梦"整理记忆。这与我们的 memory/ 日志 + MEMORY.md 双层结构是同构的，2.0.1 已验证这套模式可跑通，值得研究能否替我们做记忆维护。
- **shared cloud sessions（团队共享会话）**：多人可接入同一个进行中的 Agent 会话、接手对方上下文。这对我们"技术中心"场景（王 + 后续接入的同事共用一套招投标知识库）是很有想象力的方向——但目前是云会话，自托管下需要先评估可行性，不宜急。

**四、可直接用于流程优化的两点**
- **30 天 Usage 报表（9.6 起完整交付）**：可用于按项目/按月核算模型开销，把"AI 在招投标业务落地"的成本侧量化，这是给管理层汇报的好材料。
- **自动更新的自愈能力**：2026.10.2 之后，"升级中断"基本被解决。我们的 AGENTS.md 里还有"改 config 必须先备份 + 用 safe-gateway-restart.sh"的手工规范，升级通道更可靠后可以适度简化，但仍建议保留备份习惯。

**五、风险提示**
- 社区技能生态被反复提及是最大未解风险（技能/插件供应链）。我们装了 ClawHub 技能、feishu/tavily 插件等，建议定期用插件审计类命令核对来源，不要随手装社区技能。
- macOS 版曾出现"打不开"的构建事故（9.6 首版崩溃、9.9.7 Windows 空白工作区调用 Git 失败）。我们跑在 Mac mini 上，升级时优先用 10.x 正式版而非 beta。
