■ 1. v2026.11.3 成为 Latest 主稳定线：更新恢复与备份可靠性大修
官方 release notes 原文："This is a patch release with no new features. It fixes problems that could leave the Gateway stopped after an update, block backups on slow storage, or expose private information." 这版集中修更新器自身：包存在性检查超时后能安全恢复并保留回滚；维护锁自识别；被中断的包更新不再误报成功；大体积备份不再因所有文件共用一个 SQLite 发现截止时间而整体超时（改为分批重试，单个超大文件仍会阻塞）。同时修复"从 2026.10.10 或 2026.11.1 升级时被该超时卡住"的情况——官方明确写明已安装的更新器无法靠选更新版本拿到这个修复，需要走 update recovery 指引（#194239）。
原文链接：https://docs.openclaw.ai/releases/2026.11.3.md ｜ https://github.com/openclaw/openclaw/releases/tag/v2026.11.3

■ 2. 子代理结果边界与凭证卫生成为本版主主题
Highlights 前四条即围绕两件事。（a）子代理结果边界：私有子代理的完成结果不再进入流式聊天回复（#188490）；取消子任务后其完成回执不再阻塞父任务的交接（#178893）；工具失败未被响应时必须如实上报，不能静默地把一轮用户对话当作成功结束（#182458）；认证卡住时在 run 截止点终止并传播取消。（b）凭证卫生：插件结果按各自连接凭证隔离，Firecrawl/embedding 等搜索与记忆密钥各自绑定其目标端点；配置读取与报错中的内联环境变量凭证被脱敏；受管的 Signal 守护进程与内置语言服务器不再继承无关的 Gateway 密钥。
为什么重要：这直接对应我们"子 Agent 结果必须由父 Agent 汇总后交付"的流程——私生子代理输出不再污染用户可见回复，工具失败也不会被粉饰成"完成"。
原文链接：https://github.com/openclaw/openclaw/releases/tag/v2026.11.3

It fixes problems that could stop updates, leave scheduled reminders missing, or cause chat widgets to appear twice"。规模为 113 个 PR、53 个直接提交、64 个贡献账号。安装侧修复 Bun 1.4.4 下未装 Node 时的全局安装；并写明"安装声明了新插件 API 门槛的 2026.11.2 相关插件时，需要 OpenClaw 2026.11.2 或更新版本"。安全侧：不再把内置语言服务器的 stderr 拷进调试日志、CLI 启动不再把工作区内的 mise/XDG 路径注入子进程 PATH。

【豆浆学习笔记】
1. 版本纪律：今天的 dist-tags 实测是 latest=2026.11.3 / extended-stable=2026.9.37 / beta=2026.11.5-beta.2，本机仍是 2026.9.5 —— 本机落后 main 稳定线两个多月（9.5 → 11.3）。本机 Node v26.7.0 够 11.x，但如果王想稳一点切到 extended-stable 2026.9.37，Node 必须先升到 26.12.1+，这是纯引擎门槛，升级 Node 前需评估 macOS 上 Gateway/LaunchAgent 的兼容性。
2. 最该用的新特性其实是"边界收紧"而不是新功能：2026.11.3 把私生子代理结果挡在流式回复之外、要求工具失败如实上报。对我们的多 Agent 派发流程，这等于官方替我们兜了底——子 Agent 的中途输出不会泄漏给王，失败也不会被当成成功。建议保持现有的"子 Agent 回执必须带【任务理解】【信息缺口】"硬规则，与官方的"visible tool failures"方向一致，两边叠加更稳。
3. 更新恢复要警惕：官方原文明确写"已安装的更新器无法通过选择更新版本来获得该修复"，所以升级前先跑 `openclaw backup`、保留旧包回滚路径，别裸奔 `openclaw update`。我们已有的"改配置前先备份 + 安全重启脚本"规范正好对得上，升级时照此执行。
4. doctor 的两条提醒可直接行动：(a) browser.extensionRelay.allowLegacyAuth=true 属于旧认证兼容开关，按官方提示升级 Chrome 扩展/外部 CDP 客户端到 Relay Authentication v2 后即可关闭；(b) whisper-cli 缺模型文件，本地 STT 暂不可用，若要做会议转写需先装模型运行时。
5. 值得试的新特性（beta 线，先在副本上）：PostgreSQL 会话存储 + Boards 组件，对应我们"多项目、跨子系统、长会话"的场景，压缩后仍保留推理与活跃请求来源，对长周期跟进会议/项目很有价值；但按官方要求，必须用数据副本和独立 Gateway 做迁移演练，不要直接切生产。
