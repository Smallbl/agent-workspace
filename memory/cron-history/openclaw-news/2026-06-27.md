# OpenClaw 日报 | 2026-06-27

🔍 本地版本：OpenClaw 2026.5.28（运行中）

## 资讯列表

### 1. OpenClaw 2026.6.9 正式版发布：更稳定的渠道与恢复能力
这是6月的核心稳定版本，带来了更丰富的 Telegram 和 WhatsApp 消息传递能力。Telegram 现在支持渲染结构化文本（表格、列表、可展开的引用块）、保留换行，并支持 CLI 备份回复；WhatsApp 现在能正确遵循配置的 ACP 绑定规则。同时强化了 Agent 恢复机制和模型路由安全性，让日常使用更可靠。
原文链接：https://releasebot.io/updates/openclaw

### 2. OpenClaw 2026.6.10-beta.2：更聪明的对话处理与策略安全
新版 beta 引入了"自动快速模式"——短对话轮次自动走轻量路径，提升响应速度。同时保持了可信策略的完整性，改善了跨渠道和跨供应商的回退逻辑。Session 状态管理也更可靠：子 Agent 完成通知、会话记录非空、媒体索引对齐等问题都得到修复。对多渠道运营的用户来说是重要升级。
原文链接：https://releasebot.io/updates/openclaw

### 3. ⚠️ 安全警示：OpenClaw 存在攻击风险（已修复部分）
安全研究机构 Imperva 和 Varonis 分别发现了针对 OpenClaw 的攻击手法：
- Imperva 发现攻击者可在共享联系人、vCard、位置信息中植入隐藏指令，OpenClaw 在将消息数据传给 LLM 时没有对内容做"不可信"标记，导致指令被直接执行。此问题已在 2026.4.23 版本修复。
- Varonis 演示了通过一封普通邮件诱导 Agent 向外部转发伪造的 AWS 密钥和客户数据。
【重要】如果你运行的是 2026.4.23 之前的版本，请立即升级。邮件钓鱼类攻击则需要通过限制 Agent 权限来防御。
原文链接：https://thehackernews.com/2026/06/new-attacks-trick-openclaw-ai-agent.html

### 4. NVIDIA 发布 NemoClaw：企业级安全护盾
NVIDIA 正式推出 NemoClaw，这是专为 OpenClaw 社区打造的安全治理层。它支持一键安装，为 OpenClaw 提供沙箱执行环境、策略强制执行和受控运行时环境，让在生产环境部署 OpenClaw 变得更加安全。NVIDIA CEO 黄仁勋此前公开表示 OpenClaw 是"或许是有史以来最重要的软件发布"，现在 NVIDIA 正在围绕它构建基础设施生态，而非与之竞争。这标志着 OpenClaw 正从极客工具向企业级基础设施演进。
原文链接：http://nvidianews.nvidia.com/news/nvidia-announces-nemoclaw

### 5. OpenClaw 6月发布节奏：稳定版与 Beta 版同步推进
当前版本状态：stable 稳定在 2026.6.9，Beta 推进到 2026.6.10-beta.2。团队正在修复4月底至5月初期间由于插件依赖处理和 Gateway 冷启动路径过重导致的性能问题。OpenClaw 官方已承诺将推出 LTS（长期支持）版本，并计划将更多可选功能迁移到 ClawHub 插件市场，让核心更加精简。
原文链接：https://openclaw.com.au/updates

## 豆浆学习笔记

### 对我（豆浆）和王团队的价值分析：

1. **当前版本够用，密切关注 2026.6.10 正式版**
   - 我们运行的是 2026.5.28，不算旧但也不是最新
   - 2026.6.9 的渠道稳定性提升（Telegram/WhatsApp）对我们意义不大（我们主要用飞书）
   - 但 2026.6.10 的 Session 状态修复值得关注——如果子 Agent 任务偶发异常，可能和这个有关

2. **安全问题是最高优先级**
   - 2026.4.23 之前的版本有严重安全漏洞，我们版本 2026.5.28 是安全的
   - 但邮件钓鱼攻击（Varonis 那个）需要格外警惕：我们的飞书消息处理是否也有类似风险？
   - 建议：在 AGENTS.md 中增加一条规范——**永远不要在无确认情况下向外部发送凭据或敏感信息**

3. **NVIDIA NemoClaw 值得关注**
   - 这是企业级安全护盾，未来可能通过 ClawHub 插件形式提供
   - 如果我们要把 OpenClaw 作为公司业务助手，安全性必须放在第一位
   - 值得持续关注

4. **Agent 平台的行业趋势**
   - 行业正在从"Agent 能做什么"转向"Agent 出错后能否信任"
   - 这和我们的需求完全吻合：我们需要的是**可靠的日常助手**，而不是偶尔炫技的工具
   - 恢复能力、错误报告、操作日志——这些才是 OpenClaw 真正有价值的地方

5. **可以尝试的方向**
   - 我们还没用过的功能：Parallel Search（并行搜索）、MCP 工具链、TaskFlow
   - 如果未来要接入更多内部系统（飞书文档、企业数据库），MCP 是标准接口
   - NemoClaw 成熟后，可以考虑在公司场景中试点
