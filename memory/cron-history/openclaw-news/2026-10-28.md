**1. ⚠️【重点】2026.10.8 安全版本发布：修补 eMudhra 证书泄露**

10 月 27 日发布的 2026.10.8 是一次**纯安全补丁**（161 个 PR、163 位贡献者，无新功能）：修补了 eMudhra 证书泄露事件在 **secret egress proxy（密钥出口代理）及其导出的信任证书包**中的影响。官方明确要求：**必须重启 Gateway 才能生效**；拥有独立信任库或使用 bypass 隧道的 App 需要单独更新。

事件背景：eMudhra 因 2025 年 4 月密钥生成仪式（KGC）流程缺陷，8 个中间 CA 的私钥熵从 384 字节降到 3–8 字节，任何人几秒内即可从公开证书反推私钥，进而伪造 TLS 证书做中间人劫持。Cloudflare、Mozilla、Cisco、Palo Alto Unit 42 均已发布紧急公告。OpenClaw 的 Node 运行时下限要求（26.12.1+ / 24.22.1+）就是为此而来。

为什么重要：我们的飞书 API Key、模型 Key 都要经过 Gateway 出口代理。**这是目前唯一一条带"必须重启"的强制安全更新**，且直接关系到我经手的招投标系统凭据安全。

原文链接：https://docs.openclaw.ai/releases/2026.10.8

**2. 飞书渠道重点修复：快捷操作卡片按钮恢复 + 流式卡片跨工具调用不丢字**

2026.10.8 里有多条针对飞书的专门修复：**飞书的快捷操作卡片和确认卡片重新可以带按钮送达**（#79832，修复了很久了）；**飞书流式卡片会保留工具调用之前写下的文本**，答案续上时不会丢前半段（#182104）。同时 iMessage 不再回复自己的自发聊消息，Telegram/Mattermost 默认账号在新增具名账号后不再掉 token。

为什么重要：我们所有定时简报都走飞书推送，"卡片按钮点不动"和"流式卡片丢前半段"都是王会直接感知的体验问题——这两条修好等于简报交互体验升级。

原文链接：https://github.com/openclaw/openclaw/releases/tag/v2026.10.8

---

**3. ⭐ 定时任务稳定性修复：清理不再误删仍有子会话的 cron 会话**

2026.10.8 修复了几个直接影响我们这套"定时跑批 + 飞书推送"的机制：**定时清理不再删掉仍有活跃子会话的 cron 会话**（修复前会删父会话；已删的无法恢复）；**Agents API 定时任务在发送到自己投递目标时若未显式标记 final，不再立即停止**；**cron 脚本在插件被替换后，下次运行即可用上当前插件钩子，无需重启 Gateway**；定时公告唤醒 CLI 会话不再丢掉原生对话上下文。

为什么重要：这正是我们每天早上 9:00 跑日报简报（多子 Agent 并行 + 飞书投递）的链路。最关键的一条：**定时任务如果因为"没标记 final"而提前中止，简报会只发一半**——这个坑值得记住。

原文链接：https://docs.openclaw.ai/releases/2026.10.8

10 月 21 日官方博客发布"OpenClaw Focus Weeks"：首期（10/19–10/25）聚焦 Control UI 体验，鼓励社区成员直接在工具本身里提 issue、跑流程、试键盘导航。官方同时在招募轮值贡献者进入**共享的 OpenClaw Team 环境**（Team Server），让人和他们的 Agent 在同一环境里通过会话协作、共享上下文、甚至让 PR 携带产生它的对话上下文。

## 【豆浆学习笔记】

**今天最重要的一件事：安全更新到了，需要排期升级。**
10.8 是纯安全补丁，而且官方明确写着"需要重启 Gateway"。我们跑 2026.9.5 + Node v26.7.0——**注意：Node v26.7.0 < 26.12.1**，所以 `openclaw update` 仍会被拒绝（官方设计如此，避免装坏在跑的实例）。今天 `openclaw update status --json` 确认：latest = 2026.10.8，channel = stable，有可用更新。

**建议的升级路径（沿用我们 AGENTS.md 的红线：先备份、再确认依赖、低峰操作）：**
1. 升 Node 到 26.12.1+（或 24.22.1+），`node --version` 验证；
2. 备份 `~/.openclaw/` 与 workspace 的 `memory/`、配置；
3. `openclaw update` → `openclaw doctor --fix`；
4. **必须用 `bash ~/.scripts/safe-gateway-restart.sh`**（不要直接 `openclaw gateway restart`，会丢消息），且因为 10.8 是安全更新，重启不可省；
5. 验证：飞书收发、卡片按钮、cron 定时任务列表、日报能否完整推送。

**可以立刻用到我们工作流里的：**
- **10.8 的 cron 修复** → 我们的日报简报是"多子 Agent + 飞书投递 + 有序收尾"的典型结构，10.8 之前"未显式 final 就提前中止"会导致简报只发一半。这条修复是我们这套流水线的直接保命符，建议升级时重点回归测试一次完整日报。
- **10.8 的飞书卡片修复** → 如果王之后想用飞书卡片做"日报的确认/追问按钮"，之前按钮点不动的问题已经修好；流式卡片跨工具调用不丢字也让我们做长摘要时的排版更可控。
- **eMudhra 事件的通用教训** → 不只是 OpenClaw，我们的招投标系统如果用了自建 CA / 私有证书链，也应排查一遍。建议提醒技术中心同事。
- **Focus Week / Team Server** → 值得观察 Team Server 的"共享上下文 + PR 带对话上下文"机制，未来如果我们让多个子 Agent 协作产出招标方案文档，可以借鉴这种"上下文随产物一起流转"的设计。

**给王的一句话建议：** 今天这条 10.8 是"带强制重启的安全更新"，建议本周内安排一次低峰升级（升 Node → 备份 → 更新 → doctor → 安全重启 → 验证日报链路），我可以在您确认后按流程执行并在飞书同步每一步结果。
