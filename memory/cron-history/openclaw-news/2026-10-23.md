二、记忆系统大修：中文检索、嵌入降级、Dreaming 修复
━━━━━━━━━━━━━━━━━━━━
2026.9.7 修复了"记忆更新被漏掉"和"搜索失败"两类问题，修复了旧版 Dreaming（离线记忆整理）排程，并保护独立 QMD 文件。关键改进：当可选的嵌入服务失败时，记忆搜索可以回退到已有的关键词索引；中英混合提问中的英文词项也能被正确保留。对我们这种飞书为主、中英夹杂的工作场景，检索命中率提升是实打实的。

【豆浆学习笔记】
━━━━━━━━━━━━━━━━━━━━
1️⃣ 版本差距是最紧急的事：我们 2026.9.5，最新 2026.10.4。官方明确说"从 2026.9.5 升级的问题已在 2026.9.7 修复"，但从 2026.9.5 直接跳到 2026.10.4 仍属跨段升级，建议按知乎那篇《2026.10.4 升级科普指南》的流程走：先 `openclaw backup create --verify` 带校验备份 → `openclaw update` → 三连验证（`openclaw --version` / `openclaw doctor` / `openclaw status`）→ 刷新升级前开着的聊天标签页（官方 #168941 修复的前提）→ 发一条测试消息验证飞书通道。注意我们的 AGENTS.md 铁律：改配置前必须备份、且走 `~/.scripts/safe-gateway-restart.sh` 安全重启，不直接 `openclaw gateway restart`。这一步要不要做，等王点头。

2️⃣ 记忆系统是"第二大脑"的地基：2026.9.7 那条"嵌入服务失败可回退关键词索引"直接命中我们的痛点——现在我一旦依赖远程 embedding 掉线，中文检索就整片失灵。有回退后，检索变成"降级可用"而不是"整体失效"。同时"中英混合提问保留英文词项"正好适配我们飞书里中英夹杂的表达（比如 openclaw、doctor、backup 这类词）。建议升级后专门跑一轮 MEMORY.md / memory/ 的检索回归，确认语义检索确实生效。

3️⃣ 可直接落地工作流的新特性：
   • 远程工作区 Files / Memory / Skills → 可以把"招投标项目档案"这类资料放到远程工作区，让豆沙在飞书里直接引用项目文件，而不用每次走本地路径。
   • GitHub 阅读器（讨论 + diff 就在聊天旁边）→ 技术中心做系统建设时，评估某个开源组件可以直接在飞书里拉 diff 对比，不用来回切浏览器。
   • 30 天用量统计 → 作为主控大脑，我可以在飞书里主动汇报"本周 token/成本消耗"，这个比现在凭感觉报更可信。
   • Doctor / 更新恢复增强 → 我们已有 `openclaw doctor` 习惯，官方现在把它挪到了"历史任务标识修复"的正确位置，可以放心用 `--fix` 自动修。

4️⃣ 值得尝试的新特性：
   • Decision Models（可选决策模型）→ 适合"多方案比选"场景，比如给招标代理业务做数字化路径选型时，把决策过程外显化，减少拍脑袋。
   • Sign in with ChatGPT (Beta) 与 OpenAI Agents API 支持（2026.9.7）→ 我们当前用 MiniMax-M2.7，可作为降级/备用通道纳入 fallback 候选池，OpenAI 侧额度变化时保底。
   • Copilot 作为 embedding provider → 如果王的公司已买 Copilot Enterprise，可以统一 provider，减少第三方依赖。

5️⃣ 风险提示：官方 2.0 之后迭代极快（2026.9.6 一个版本就有 2,614 个 PR、350 位贡献者），10 月中旬已出现"从 2026.10.1 首次升级报错"的公开问题。我们的应对策略是——稳定通道优先（需要 LTS 语义可用 `openclaw update --channel extended-stable`，官方 2026.9.33 就是 gateway-only 的 extended-stable 版本），不要盲目追最新小版本；每次升级前做带校验备份，保留回滚路径。

6️⃣ 待王决策：一是我是否执行 2026.9.5 → 2026.10.4 的升级（需要备份 + 安全重启窗口）；二是是否要把"每周主动汇报用量与成本"作为固定动作加入日报流程。
