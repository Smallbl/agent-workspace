一、v2026.11.1 发布：可靠性补丁，修复「消息被拒」与「Doctor 假成功」
83 个 PR、91 次直接提交、67 位贡献者。该补丁不含新功能，核心是修掉两类让人抓狂的故障：其一，消息已经被接收却随后被拒绝——Telegram 会给出虚假的「重启」拒绝提示或在处理中丢失兜底回复，Discord 也会在等待处理时把已接收的消息拒掉；其二，Doctor 检查失败却报告成功，现在检查受阻或修复未完成会返回非零退出码（用 `doctor --json` 的脚本要注意这个变化）。此外 Gateway 配置写入卡住、设置变更长期挂起的问题也一并修好。重要性在于：这是典型的「信任修复」——自动化运维脚本此前可能把失败当成功，静默掩盖故障。

原文链接：https://docs.openclaw.ai/releases/2026.11.1

二、2026.10.10 稳定版与 extended-stable（LTS）并行发布
项目现在维持两条发布线：主稳定线 2026.10.10（11 月 3 日发布，标为 Latest），以及只面向 Gateway 的 extended-stable 线 2026.9.36（10 月 29 日发布），后者相当于当前的 LTS——包含 2026 年 9 月底的代码加关键安全更新、可靠性与性能修复及新模型支持（如 Kimi K3.1 Pro）。这意味着企业用户可以锁定 LTS 线降低变更频率，稳定版用户则持续拿到新功能。

原文链接：https://github.com/openclaw/openclaw/releases

三、强制升级 Node 运行时：拒绝在存在证书风险的旧 Node 上安装
OpenClaw 现在要求 Node 24.22.1+（24 线）或 26.12.1+（26 线），以拒绝被 2026 年 10 月 Node.js 安全公告中泄露证书签名的 TLS 链。Docker 镜像自带 Node 24.22.1，安装器会自动选择已修补运行时，`openclaw update` 在旧 Node 上会拒绝执行并给出恢复指引，而不是把现有安装搞崩；源码构建锁定 pnpm 12.15.0。这是一条硬门槛式的安全基线，值得在自己的 Mac mini 上确认。

原文链接：https://github.com/openclaw/openclaw/releases

四、大规模安全加固：凭证脱敏、工作区与备份边界收紧
近几个版本密集修复了凭证泄漏面：浏览器配对凭证不再进入进程参数、Google OAuth 客户端密钥在日志中脱敏、MCP CLI 检查结果中的凭证被抹除、Fish Audio 与 Gradium 等提供商错误中的凭证脱敏；PostgreSQL 的 Git 导出统一加 `--exclude-secrets`，捆绑插件的 token、OAuth 凭证、签名密钥、webhook token 均被脱敏还原。同时 Discord 附件下载不再继承宽泛的浏览器私网权限，ClawHub 限制私网下载与跨源重定向（ClickClack 阻止指向私网 HTTP 地址的跨源跳转）。对把敏感配置放进 OpenClaw 的团队来说，这是「别再把密钥写进日志」的正面进展。

原文链接：https://github.com/openclaw/openclaw/releases
文档：https://docs.openclaw.ai/releases/2026.11.1

五、记忆与长会话能力的实际提升
v2026.11.1 中，大体量会话历史与归档可以以更少的工作内存完成读取与索引，并支持在相邻大消息间导航；大型导出与记忆准备期间，其他 SQLite 操作等待时间下降。长期会话在超长一轮之后仍能保留有用的近期上下文，重复压缩不会丢失当前请求。2026.10.7 也带来「可重放安全」的会话恢复：被中断的会话保留恢复来源与未完成的工具结果，被拒绝的 Claude CLI 草稿不会进入最终回复，大批量子会话完成也不会撑爆发起方的上下文。对长期运行的 agent 来说，这些直接决定记忆可靠性。

【豆浆学习笔记】

一、对我们最直接的可用项
1. `doctor --json` 退出码语义变了：检查受阻或修复未完成现在返回非零。这意味着我们可以放心把 `openclaw doctor` 接入日常巡检脚本——以前「假成功」会让巡检形同虚设，现在失败能被真实捕获。这条建议立刻可落地。
2. 本地版本落后较多（2026.9.5 vs 稳定 2026.11.1）。好消息是 2026.9.5 正好是官方指定的「六月前旧安装升级必经的桥接版本」，所以升级路径是通的。但 Node 版本是硬门槛：需要 24.22.1+ 或 26.12.1+，我们当前是 v26.7.0，升级前必须先升 Node，否则 `openclaw update` 会直接拒绝。当前机器 node=v26.7.0（未达 26.12.1，24 线亦未知），这是升级前的前置动作，需要和老板确认时间窗口。
3. 「先只读两周」的社区实践对我们的招标业务场景同样成立：让豆浆先只做读取、汇总、提醒，写操作（发送邮件、提交文件、改生产配置）保留人工确认。这与 AGENTS.md 里「外部动作先问」的规则是一致的，值得再往下压实成清单。

二、可直接套用到我们工作流的新能力
1. 「可重放安全」的会话恢复 + 大体量归档低内存索引 → 对我们「多项目并行 + 长会话 + 记忆持久性」的要求是直接利好。特别是「被拒绝的草稿不进入最终回复」「大批量子会话完成不撑爆发起方上下文」，正好命中我们用 sessions_spawn 派发子Agent 的场景，可以降低子Agent回执丢失或父会话上下文爆掉的风险。
2. 会话超长后保留近期上下文、重复压缩不丢当前请求 → 对我们「跨天跨项目的持续跟进项目进度」是刚需，因为我们经常在一条会话里连做多件事。
3. 配置改动热更新（`openclaw config set` / `openclaw setup` 走运行中的 Gateway，不强制重启）→ 这直接命中 AGENTS.md 里那条「Gateway 重启安全规范」的痛点。改配置不再丢消息的风险显著降低，重启脚本的必要性下降。不过我们仍建议保留安全重启脚本作为兜底。

三、值得试的新特性 / 需留意
1. Gemini Flash 官方端点默认切到 Interactions API，请求参数、密钥轮换与采样更一致；但自定义端点默认走 GenerateContent，且 Interactions 会忽略显式缓存句柄——如果我们要用 Gemini 并依赖提示缓存，需要选 `google-generativeai` provider。这是模型侧的隐性开关，别踩坑。
2. Android 端 Talk 结束后，已接受的任务现在能跑完并把答案落到聊天里；原生 App 的语音/相机能力（Talk、屏幕录制、摄像头）持续增强。如果我们需要手机端随时追问项目进度，值得配一台 Android 节点试用。
3. 语音通话在未指定回复模型时会用 call agent 的配置模型；长语音回复可排队播放。这些对「会议中快速追问」场景有想象空间，但我们目前主要是文字协作，优先级靠后。
4. 备份与导出的 `--exclude-secrets` 默认化是个提醒：我们的 `~/.openclaw` 目录若要纳入 Git，必须显式排除密钥，否则会把凭证带进版本历史。建议给工作区配置一份 .gitignore 或改用带脱敏的备份方式。
