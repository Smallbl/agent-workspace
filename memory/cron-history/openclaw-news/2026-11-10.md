二、资讯 5 条
1. v2026.11.2（latest 主稳定线）发布：纯补丁版、无新特性
   113 个 PR、53 次直接提交、64 个贡献者。集中修三类问题：更新流程被卡住、定时提醒丢失、聊天小部件重复出现。安装侧修复了 Bun 1.4.4 无 Node 时的全局安装问题。
   https://docs.openclaw.ai/releases/2026.11.2

2. 定时/自动化链路大幅加固（对每日简报类 cron 影响最直接）
   修复了"定时提醒文本里提到 heartbeat 或 wake 时提醒消失"的问题（#129650）；修复定时 CLI 运行未使用记录账号、Discord 通知用错身份；保留正在运行的 cron 会话不被保留策略清理；cron 编辑时留空的告警字段不再残留旧值。
   https://docs.openclaw.ai/releases/2026.11.2

3. 飞书通道修复：流式文本跨工具调用丢失 + 动作卡片格式错误
   写在 v2026.11.1（83 PR / 91 提交 / 67 贡献者，纯补丁）。这条对本工作区直接影响——飞书回复中若含工具调用，流式输出可能丢字；动作卡片曾以错误格式发出。
   https://docs.openclaw.ai/releases/2026.11.1

4. Doctor 现在会正确失败：检查被阻断 / 配置无效 / 迁移被延后时返回非零退出码
   之前会"报成功"。脚本化调用 doctor --json 需要处理新的退出状态。另外 unattended 模式下 doctor 只报告缺失插件、不擅自安装，除非给 --fix/--repair/--yes。
   https://docs.openclaw.ai/releases/2026.11.1

5. 配置热更新有了明确语义：写入已保存但需重启 = applied-restart-required / restart-pending
   源码实证（npm pack openclaw@2026.11.2，grep dist/config-*.mjs、dist/server-reload-managed-*.mjs）：存在 outcome 字符串 applied-restart-required 与 restart-pending，提示语为"persisted but was not applied to the active Gateway ... run config.get, then use config.apply to reapply or restart"。v2026.10.10 官方原文也写明"可在不停止本地 Gateway 的情况下修改支持的设置与供应商配置，但部分首次设置与 CLI 凭据命令仍需停机，保存的变更可能需要 reload 或 restart 才生效"。结论：热更新存在，但不是全部，敏感变更仍以 restart-pending 为准。
   https://docs.openclaw.ai/releases/2026.10.10

【豆浆学习笔记】
1. 升级优先级最高的是"定时提醒丢失"和"飞书流式丢字"这两条，都直接打在日常流水线上。本机 2026.9.5 距 latest 隔着 9.6~9.36、10.x、11.1、11.2 整段，建议排一次受控升级；因为 extended-stable 2026.9.36 的 Node 门槛高于本机 Node，升级前需先把 Node 提到 v26.13.0 或 v24.22.2。
2. 值得试的新特性：2026.10.10 的 Chat Details 面板（对话旁直接看详情）、Advisor（任务中途给出纠偏建议）、浏览器 Talk 的分离语音模式——Advisor 恰好对应我们 AGENTS.md 里"子Agent 回复前自检"的人工版，可以先本地观察它的判定口径，再决定是否把 Advisor 口径写进派发格式。
3. 可直接应用的改进：
   - 把"cron 提醒文案不写 heartbeat/wake 字样"作为硬规则固化（避免命中 #129650 的丢失路径）。
   - 飞书回复尽量单条发出、避免依赖跨工具调用的流式续写，降低流式丢字风险。
   - 把 doctor 纳入每日巡检脚本，重点看"agent directories without matching agents.entries entry"和 session SQLite issue 计数；本机 2 个孤儿目录 + 1354 个 session SQLite issue + 无备份，建议做一次 doctor --fix 加 openclaw backup create。
   - 配置变更尽量走 config.set + 观察 outcome，而不是直接重启 Gateway；拿到 applied-restart-required 再按脚本重启。
4. 飞书运维建议：把 backup enable 纳入每日定时，让备份从"无记录"变成有版本链，这是当前最大的单点风险。
