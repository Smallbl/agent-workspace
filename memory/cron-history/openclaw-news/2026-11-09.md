二、资讯 5 条

1. 【2026.11.2 发布：主题是"隐私与信任边界"，不是新功能】
这是 2026-11-08 19:31 UTC 上线的版本，已被 npm 实测标为 latest。官方 Highlights 第一条原文即 "Privacy and trust boundaries: Keep configuration secrets, conversation content, tool errors, and channel payloads out of diagnostic logs, enforce the selected provider and navigation trust boundaries, and release MCP grants after warm CLI turns."
为什么重要：我们是招标代理场景，飞书里的投标文件内容、供应商报价都属于商业机密，这版把"配置密钥 / 会话内容 / 工具报错 / 渠道载荷"从诊断日志里剥离，对我们是最贴身的合规改进。规模 115 个 in-range PR。
原文：https://github.com/openclaw/openclaw/releases/tag/v2026.11.2

2. 【诊断日志"减负"：主动降级保响应速度，代价是取证细节变粗】
官方 Changes 原文："Optional diagnostic content capture now bounds attribute and candidate payload sizes and omits oversized image data, reducing diagnostic payload fidelity to protect Gateway responsiveness; this does not limit prompts or conversation history."
为什么重要：明确说明只是限制"诊断采集"而不影响提示词和会话历史——我们排查问题时仍能拿到完整上下文，只是不能指望诊断包里有大图和超长载荷。配合 Highlights 里 "Reduce diagnostic capture work and avoid blocking the Gateway on plugin cleanup"，Gateway 不再因插件清理或病态 Telegram 表而被拖住。
原文：https://github.com/openclaw/openclaw/releases/tag/v2026.11.2

3. 【定时投递不再"张冠李戴"：保留发送者与账号身份】
官方原文："Account-safe delivery: Preserve sender and account identity across durable retries and scheduled delivery, recover WhatsApp identity lookup, and retain Teams routing and allowlist settings across reloads."
为什么重要：直接命中我们最核心的用法——每天的 OpenClaw 日报、AI 早晚报等多条 cron 简报。原文另有一条 "Scheduled account continuity: Preserve account selection and delivery continuity for required scheduling repairs"。此前重试可能把内容发错账号/发成别人名义，现在身份被持久化。
原文：https://github.com/openclaw/openclaw/releases/tag/v2026.11.2

4. 【记忆与嵌入三处修复，其中一条是我们的刚需】
官方原文："Memory and embeddings: Bound assembled recall context, accept the memory-search limit alias, and forward the Azure OpenAI embedding API version correctly."
为什么重要：我们的记忆体系高度依赖 memory_search 的召回质量。"Bound assembled recall context"是给召回上下文设上限——好处是防止单次召回撑爆上下文，代价是超长召回会被截断，检索策略需要相应调优；"accept the memory-search limit alias" 说明之前用别名传 limit 会静默失效。配合 Highlights "Bound assembled recall context"，我建议升级后专门做一次召回量对照测试。
原文：https://github.com/openclaw/openclaw/releases/tag/v2026.11.2

5. 【更新与恢复加固：macOS 权限、更新自锁死、插件执行路径保留】
官方原文："Safer recovery and updates: Preserve configured plugin executables and environment references through updates, repair macOS service recovery when Trash access is denied, and avoid update self-fencing and interrupted-update hangs."
为什么重要：我们这台就是 macOS，"Trash access is denied"（废纸篓权限被拒）导致服务恢复失败，正是我 AGENTS.md 里 "trash > rm" 策略可能触发的真实故障场景，值得纳入升级验证清单。另外 "update self-fencing"（更新把自己锁死）和 "interrupted-update hangs"（中断更新挂起）对应 extended-stable 线 2026.9.36 的"失败回滚不再丢包"，两个版本是同一主题的两面。
原文：https://github.com/openclaw/openclaw/releases/tag/v2026.11.2

四、配置写入 / 重启行为（源码证据）
npm pack openclaw@2026.11.2 解包后 grep dist 命中：applied-restart-required 7 次、restart-pending 6 次、restartRequired 59 次、restart required 4 次。源码原文提示：
- "applied-restart-required" → "persisted and updated the active Gateway, but a recovery restart is required; wait for the Gateway to restart, then run config.get to confirm the active revision"
- "restart-pending" → "persisted and was accepted for restart; wait for the Gateway to restart..."
结论：配置写入存在"已落盘但需重启才生效"的分支，不能断言"改配置不强制重启"或"不再丢消息"。这与 AGENTS.md 的 Gateway 重启安全规范（safe-gateway-restart.sh + 10 秒缓冲）方向一致。

【豆浆学习笔记】
1. 本周主线已从"功能"转向"边界"：2026.11.2 的六条 Highlights 全部围绕隐私、身份、可用性、恢复安全，没有一条是"加了个新功能"。这是典型的"基础设施收敛期"信号——上游在把重心从堆功能转向收紧信任边界。我们的适配策略应同步调整：不再追新功能，而是把升级重点放在"验证边界行为是否变化"。
2. 立即可用的改进（不改版本也能做）：doctor 报 "No successful backup is recorded"，且刚经历一次 2026.11.2 更新线修复 macOS Trash 权限导致的服务恢复失败。建议本周做一次 openclaw backup create 并配置 schedule —— 这与 AGENTS.md "配置/安装前置检查必须先备份"是同一条原则，只是把它落到 OpenClaw 自身的状态上。
3. Doctor 数据治理要排期：1354 个 session SQLite issue + 2 个孤儿 agent 目录 + 未配置的 command owner。这三项都不是故障，但都会在关键时刻掩盖真问题（Doctor 假成功、子 Agent 走默认模型、无人能执行 /update）。建议按"先 doctor --fix 迁移 SQLite → 再补 agents.entries → 最后配 command owner"三步走，每步单独验证。
4. 记忆系统需要一次回归：2026.11.2 的 "Bound assembled recall context" 给召回设了上限。我们现在的 memory_search 用法（memory/ 目录 + 语义检索 + 大批量读取）正好踩在这条上，升级后务必做一次"同一 query、不同 maxResults"的召回对照，看截断点落在哪。
5. 安全优先级再次确认：本机 Node 26.7.0 低于 26.12.1 安全修复版，而 26.13.0 已是 Latest LTS。同时 2026.9.36 的 engines 直接要求 >=26.12.1。也就是说无论走 latest 线还是 extended-stable 线，Node 都必须先升到 26.13.0。顺序：先 Node，后 OpenClaw，配置按 safe-gateway-restart.sh 走。
6. 一个方法论提醒：今天 version 事实全部来自当次 npm 实测，没有沿用昨天记忆里的 latest（昨天是 2026.11.1，今天已变成 2026.11.2）。日报类任务若复用前一天的数字，就会系统性地慢一拍——这正是"版本事实判据"规则存在的原因，值得保留为固定校验点。
7. 2026.11.2 官方 notes 在 docs 站点和仓库 CHANGELOG 目录都还没上线（404，阳性对照已确认抓取逻辑正常），只能从 npm 包和 GitHub Releases 拿。今天这属于"官方发布渠道尚未同步"，不是"没有发布说明"——下次日报可再确认是否已补齐。
