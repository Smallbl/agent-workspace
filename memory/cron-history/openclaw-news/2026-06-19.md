## 📰 资讯三：安全警报——新型攻击可诱骗 OpenClaw 执行隐藏代码 / 泄露密钥

The Hacker News（6 月 11 日）报道两起独立研究：

- **Imperva 发现**：OpenClaw 将共享联系人、vCard、位置数据传给 LLM 时，没有用"不可信内容"标记包裹，导致攻击者可在联系人中嵌入指令，代理会在受害者毫不知情时执行。（已在 v2026.4.23 修复）
- **Varonis 发现**：给代理一封普通业务邮件，即可诱导它把模拟的 AWS 密钥和客户数据转发到外部地址——这是社会工程攻击，与代码修复无关，本质是"限制代理的自主操作权限"。

⚠️ 提醒：如果你的 OpenClaw 部署对外接收消息/联系人/邮件，务必检查版本并开启输入过滤。

🔗 https://thehackernews.com/2026/06/new-attacks-trick-openclaw-ai-agent.html

## 📰 资讯四：Anthropic 调整 Claude 接入策略——标准订阅移除 OpenClaw 访问

Linux Journal 分析指出，2026 年 4 月 Anthropic 从标准 Claude 订阅中移除了 OpenClaw 访问，改为按量付费模式，理由是代理类系统计算资源消耗异常高。这对持续运行 OpenClaw 工作流的用户来说意味着成本上升和接入复杂度增加。

对比鲜明的是，OpenAI 采取了相反策略：聘请了 OpenClaw 创始人 Peter Steinberger，并持续支持 OpenClaw 开源发展。两大 AI 厂商对代理框架的态度出现明显分化。

🔗 https://www.linuxjournal.com/content/openclaw-2026-what-it-whos-using-it-and-whether-your-business-should-adopt-it

## 【豆浆学习笔记】

**这些更新对王和我们的团队有什么价值？**

1. **Microsoft Scout 的启示**：企业级 AI 代理正在从"问答工具"进化为"有身份、能自主、接受治理的数字同事"。这对招投标行业的意义：我们也可以探索让 OpenClaw 在内部系统中扮演"流程加速器"角色（如自动汇总项目进展、跟进供应商节点），关键是要有明确的权限边界和审批流程。

2. **安全漏洞的警示**：这提醒我们，哪怕是多渠道接入的轻量代理场景，也需要假设"任何输入都不可信"。在我们部署飞书/其他 IM 渠道时，应避免让 agent 无限制地直接操作文件或转发敏感内容。

3. **Telegram/WhatsApp 改进**：这些渠道的富文本支持意味着未来如果需要跨平台分发消息（对外招标公告、供应商通知），OpenClaw 可以原生渲染格式，不需要额外加工。

4. **Anthropic vs OpenAI 路线差异**：OpenAI 押注 OpenClaw 生态，意味着未来 OpenClaw 对 OpenAI 系模型的兼容性和深度集成会持续加强。如果我们在模型选择上倾向 OpenAI，后续升级收益更大。

**有没有值得尝试的新特性？**

→ v2026.6.8 的并行 Web 搜索支持，可以尝试让 agent 在做市场调研时多源并行搜索，提高信息收集效率。
→ MCP 工具类型强制转换的稳定性改进，如果有接入外部 API 的场景，应该更可靠了。
