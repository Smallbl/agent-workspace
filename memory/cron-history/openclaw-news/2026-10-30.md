1️⃣ 【v2026.10.7】更新/修复专项补丁：升级链路与"丢消息"问题集中收口
━━━━━━━━━━━━━━━━━━━━
10 月 24 日发布的 2026.10.7 是一次纯补丁版本（61 个 PR、54 位贡献者），几乎全部精力都放在"让升级更稳、让消息不丢"上。核心修复包括：修复 Bun 环境下因数据库访问检查过早超时导致的 Gateway 启动失败；修复插件重载前排队的回复无法送达（现在会用当前 provider 正常投递）；修复长会话被 provider 截断后无法继续、以及被压缩/中断的会话丢失原始请求和工具结果的问题；新增"大批量子 Agent 结果自动压缩摘要后再交回主 Agent"的机制，避免父 Agent 被超长完成消息淹没。
为什么重要：我们每天跑的定时简报、多 Agent 派发都依赖"消息必达 + 会话可续"，这一版正好把这两类痛点堵住了。
原文链接：https://docs.openclaw.ai/releases/2026.10.7

2️⃣ 【v2026.10.6】安全更新：eMudhra 证书泄露事件修复
━━━━━━━━━━━━━━━━━━━━
这是一个没有新功能的紧急安全补丁（233 个 PR、149 位贡献者），专门修复 eMudhra 证书颁发机构被入侵导致的供应链风险，要求自管 Node 的用户必须先升级到 Node 24.22.1+（Node 24 分支）或 26.12.1+（Node 26 分支）再启动 OpenClaw。同时修复了会让全新 Windows 安装、Doctor 诊断和 Gateway 启动直接失败的"离线维护"误报与数据库错误。
为什么重要：这是官方主动披露的证书供应链事件，属于必须跟进的强制项，不是可选升级。
原文链接：https://docs.openclaw.ai/releases/2026.10.6

3️⃣ 【v2026.10.5】Skill Workshop 2.0 + 全新侧边栏 + 公开会话链接
━━━━━━━━━━━━━━━━━━━━
这是 10 月的重磅功能版本（2,250 个 PR、637 位贡献者）。Skill Workshop 升级到 2.0：可以查看"学到的技能"是怎么变化的、支持版本对比、保存历史版本、Undo 撤销、归档/恢复，所有编辑动作集中在同一个库里；侧边栏重做，Agent 列表更易读、支持搜索与置顶，Subagents 与 Processes 面板直接挂在父会话旁边，可随时查看子 Agent 状态、耗时和命令输出并就地 Stop；同时发布的会话可以直接用常规聊天链接打开，拿到链接的人无需登录即可阅读（官方提示脱敏只是尽力而为，关掉分享也无法收回已保存副本）。
为什么重要：Skill Workshop 决定了"我的工作经验能否沉淀成可复用流程"，侧边栏则直接决定多 Agent 协作的可见性和可控性。

4️⃣ 【v2026.10.1】已安装技能发现、MCP Apps 与完整备份
━━━━━━━━━━━━━━━━━━━━
10 月 10 日发布的 v2026.10.1（396 个 PR）带来了"已安装技能发现"——Agent 能主动看到系统里装了哪些 skill 并按需选用；引入 MCP Apps（标准化的 MCP 应用接入）与完整备份能力，并对聊天、原生 App、自动化任务做了大范围更新。官方文档同时强调：升级后子 Agent 的完成消息在孙 Agent 投递挂起时也能正常送达，后续消息不再截断正在返回的结果。
为什么重要：技能可被发现 + MCP 应用化，是把外部系统（飞书多维表格、知识库等）稳定接入 Agent 体系的标准路径。

5️⃣ 【OpenClaw 2.0 / v2026.8.1】年度最大版本回顾：多人协作会话、内存整合、权限体系
━━━━━━━━━━━━━━━━━━━━
虽然已发布近两个月，但仍是理解当前架构的主线：v2026.8.1（对外称 OpenClaw 2.0，8 月 31 日发布）合并了超过 16,000 个 PR、933 位贡献者，约占该项目历史全部 PR 的一半。六大新能力：引导式安装配置、彻底重做的浏览器端应用、多人共享云会话（可加入进行中的会话、带着完整上下文交接任务——官方团队自己就是这么开发 OpenClaw 的）、内置统一内存（含后台整合与自我学习，可把经验转成技能提案）、Skill Workshop、可审计的权限体系（授权绑定到具体的请求/命令/会话/人，会话可设为只读、受限、工作区或完全访问，团队凭据库为只写）。
注意：会话数据迁移到 SQLite，OpenProse 插件被移除，codex/ 模型路由改名为 openai/，升级前务必备份并执行 openclaw doctor --fix。

📌 对我们的价值排序

1️⃣ 【最高优先 · 安全】eMudhra 证书泄露补丁（2026.10.6）必须跟进。我们这台是 Mac mini + Node v26.7.0，而官方要求 Node 26.12.1+ 才算安全——也就是说我们当前 Node 版本低于安全基线，需要在升级 OpenClaw 前先升 Node。两者有先后顺序：先 Node，后 OpenClaw。

2️⃣ 【直接可用 · 升级到 2026.10.7】我们本地还在 2026.9.5，落后约 12 个补丁版本。10.7 里"插件重载前排队回复无法送达""长会话截断后无法继续""大批量子 Agent 结果淹没父 Agent"这三条，正好命中我们每天的定时简报 + 子 Agent 派发场景。建议安排一次升级（升级前按 AGENTS.md 规范备份 + 走 safe-gateway-restart）。

3️⃣ 【值得试 · Skill Workshop 2.0】我们的招投标流程（标书编制、公告核对、供应商资质审核、评委抽取等）大量是可复用的固定动作。目前这些知识散落在 AGENTS.md 和 MEMORY.md 里，Skill Workshop 的"提案→评审→版本对比→Undo"流程能让它变成一份份独立、可审计、可回滚的技能包。而且它明确区分了"个人事实进 memory、仓库知识进项目文档"——和我们现在的双轨记忆设计正好一致。⚠️ 但社区有明确质疑帖（Reddit）指出它"难以使用且有风险"，所以我的建议是：先只开"提案评审"模式，不要开自动写入，用几周观察质量再决定是否放开自动学习。

4️⃣ 【值得试 · Subagents / Processes 面板】我们靠 AGENTS.md 里的"主 Agent 绝不自己写代码"铁律派发前端官/后端官/测试官。有了 10.5 的新面板，子 Agent 的状态、耗时、最近命令输出可以实时查看和就地 Stop——相当于给我们的多 Agent 纪律配了一个可视化监控屏，排障时不用再去翻会话历史。

5️⃣ 【观察 · 公开会话链接】把飞书会话链接匿名可读这个能力，用来分享"项目跟踪系统"的使用演示很方便；但官方自己都提示脱敏只是尽力而为且关掉分享也收不回已保存副本。所以这条我建议只用于演示场景，绝不用于涉及客户/供应商信息的会话。

6️⃣ 【关注 · 多人共享云会话】等我们把"招标项目跟踪"这类多人协作场景真正跑起来时，这是让王和同事直接加入我正在跑的会话、带着上下文交接的关键能力，比现在"发消息让豆浆重跑一遍"高效得多。

⚠️ 风险提醒
• 升级前必须备份配置与数据（会话迁 SQLite，回滚版本看不到新会话）。
• 升级后跑 openclaw doctor --fix 清理迁移遗留配置。
• 我们自建技能多，"插件 SDK 弃用路径"（部分子路径有 9/30、10/1 移除期限）需要检查一遍，避免升级后静默失效。

🛠️ 建议下一步（等你点头我再动）
• 升级 Node 到 26.12.1+（安全基线）
• 升级 OpenClaw 到 2026.10.7（走备份 + safe-gateway-restart）
• 把 Skill Workshop 设为"仅提案"模式，挑一个招投标文档核对流程做试点
