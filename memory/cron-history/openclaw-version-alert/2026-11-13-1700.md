【2026.11.3 是否有重大变化 / 值得升的依据（逐字引自权威源）】

  ⇒ 结论：此前「macOS LaunchAgent 在更新维护期间重启」的担心，在 2026.11.3 中**已有官方修复条目**，不是传闻。

tag 版 Highlights 原文（来源：https://raw.githubusercontent.com/openclaw/openclaw/v2026.11.3/CHANGELOG/2026.11.3.md）：
- 「**Private task results:** Keep private subagent completions out of streamed chat replies. (#188490)」
- 「**Visible tool failures:** Report unanswered tool failures instead of silently ending a user-addressed turn as a success. (#182458; related #99645)」
- 「**Sandboxed image access:** Keep required-sandbox image previews inside allowed folders, even in Full Access mode, while preserving explicit administrator image allowances. (#176203)」

【安全事件本机实证（R11 + 第 10 条）】
eMudhra / CVE-2026-111943 相关：
- 本机 Node 26.7.0 的 `tls.rootCertificates` 中 eSign/eMudhra 家族共 **4 张**
  （emSign Root CA - G1、emSign ECC Root CA - G3、emSign Root CA - C1、emSign ECC Root CA - C3）；
  其中精确匹配 `CN=emSign ECC Root CA - G3` 的为 **1 张**。
- 本机 Node 版本 26.7.0 与官方修复版本（22.23.4 / 24.22.1 / **26.12.1**）的差距：26.7.0 < 26.12.1
  ⇒ 本机 Node 自带根证书库**仍含受影响根**，本机在「Node 自身根库」这一层面仍信任受影响链。
- OpenClaw 侧的缓解措施在 **2026.10.8** 发布，原文（来源：https://docs.openclaw.ai/releases/2026.10.8.md 第 10 行）：
  「**Security release:** v2026.10.8 adds remediations for the eMudhra certificate compromise in the secret egress proxy and its exported trust bundle.
   Restart the Gateway to apply the change. Apps with independent trust stores and bypass tunnels need their own updates.」
  ⇒ 注意：2026.10.8 的 engines 为 `>=24.22.1 <25 || >=26.12.1`，**本机 Node 26.7.0 暂不可装**；
  但 2026.10.10 与 2026.11.3 均晚于 10.8 且 engines 满足本机，升级即涵盖该修复（10.10/11.3 自身 release notes 中
  eMudhra 关键词命中数为 0，即未重复声明该修复，而非修复被撤销）。
- 结论：**升级到 2026.11.3 可覆盖 OpenClaw 侧的 eMudhra 缓解**；但若关心的是「Node 自带根证书库」本身，
  仍需把 Node 升到 26.12.1+ 才能移除受影响根（两条不互斥，见路径 B）。

【升级前置（openclaw doctor 实测，观测时刻 2026-11-13 17:07:29 CST）】
以下数字均为本次 doctor 输出的实测值，迁移会持续推进、数字会漂移，核对时请以此观测时刻为准。
1. **Session SQLite 未迁移（必须先处理）**：doctor 报「- Legacy entries: 1377; SQLite entries: 1371.」
   与「- Found 1354 session SQLite issue(s). Inspect with "openclaw doctor --session-sqlite dry-run --session-sqlite-all-agents".」
   → 处理方式：先停 Gateway，再执行
   `openclaw doctor --session-sqlite recover --session-sqlite-all-agents`（或 `openclaw doctor --fix`）。
   **不要带着未迁移的会话直接升级。**
2. **无 command owner（授权缺失）**：doctor 报「No command owner is configured.」——`commands.ownerAllowFrom` 未设置，
   ⇒ `/update`、重启 Gateway、改配置均无授权主体。升级前需先配置 command owner。
3. **孤儿 agent 目录**：doctor 报「Found 2 agent directories on disk without a matching agents.entries entry」
   （其中提到 ~/.openclaw/agents/agent-memory/openclaw-agent.sqlite）→ 可作清理项，或恢复缺失的 agents.entries 条目。
4. **明文密钥告警（安全）**：doctor 报 openclaw.json 含明文密钥字段 —— gateway.auth.token、
   plugins.entries.tavily.config.webSearch.apiKey、channels.feishu.accounts.main.appSecret、
   channels.feishu.accounts.zhanling.appSecret。建议迁移到 SecretRefs（`openclaw secrets configure` / `openclaw secrets apply`）。
5. **桥接版本前置已满足**：官方 https://docs.openclaw.ai/install/updating 的「Upgrading very old versions」原文：
   「For installations older than July 2026, upgrade to **`2026.9.5` first**, run its Doctor migrations, and then upgrade to `latest`.」
   本机当前正运行 2026.9.5（发布于 2026-09-19，晚于 2026 年 7 月）⇒ 桥接要求已满足，可直接升到 latest。
6. **准入门槛 vs 安全地板（非互斥）**：engines 满足 = 能装能跑；`NODE_SECURITY_RELEASE_FLOORS`（26.12.1）只是建议，
   OpenClaw 不会因此拒绝安装。⇒ 升到 2026.11.3 **不需要**先升 Node。
